# รูปแบบการตัดต่อ — คลิปอ้างอิงจาก TikTok @noob_editor100

เอกสารชุดนี้ถอดรูปแบบการตัดต่อของคลิปทั้ง 7 ตัวใน [`Tiktok/`](../../Tiktok/)
ออกมาเป็นรายไฟล์ เพื่อเอาไปตั้งค่าใน vcut

ตัวเลขทุกตัวในเอกสาร**วัดจากไฟล์จริง** ด้วย `ffprobe` · `scdet` (ตรวจรอยตัด) ·
`silencedetect` · `ebur128` (ความดัง) และการหาคาบด้วย autocorrelation ของ onset envelope
ไม่ใช่การกะจากการดู

## สองฟอร์แมตที่ต่างกันคนละเรื่อง

### แบบ A — มาสคอต 3D + ตัวหนังสือเคลื่อนไหว (คลิป 01 · 02 · 03 · 04 · 05)

พื้นกระดาษยับแดงเลือดหมูสลับดำสนิท · มาสคอตหมวกปีกแว่นขาววางทับตลอด ·
ตัวหนังสือไทยหนา ขาวขอบดำ **เน้นคำสำคัญด้วยแดง #E0102A คำเดียวต่อประโยค** ·
ทรานสิชัน glitch/RGB · การ์ดปิดท้าย TikTok 4.00 วิ

**vcut ผลิตได้ทั้งโครงเรื่อง จังหวะ และหน้าตาแล้ว — เหลืออย่างเดียวที่ต้องเตรียมไฟล์
มาเองคือมาสคอต 3D** ซึ่งต้องเรนเดอร์เป็นไฟล์ช่องอัลฟาแล้ววางเป็น `overlays` โดยใช้
**ProRes 4444 (.mov)** — ไม่ใช่ `.webm` (ดู [แผนอุดช่องว่าง](PLAN-closing-the-gaps.md) ข้อ 0)

ส่วน glitch · ตัวหนังสือทีละคำ · ตัวเลขนับ · เส้นนีออน อยู่ในเอนจินหมดแล้ว

### แบบ B — Before | After เทียบข้าง (คลิป 06 · 07)

ครึ่งบนแบ่งสองช่อง ครึ่งล่างเป็นสกรีนเรคคอร์ดไทม์ไลน์ CapCut ที่กำลังเล่น

**คลิปสองตัวนี้ไม่ใช่ "คลิปที่ตัดสวย" แต่คือ "คลิปที่แสดงการตัดให้ดู"** —
ช่อง After คือหนังที่ตัดเสร็จ ช่อง Before คือฟุตเทจดิบตัวเดียวกัน

**ตอนนี้ vcut ผลิตทั้งใบได้แล้วด้วยคำสั่งเดียว** — `vcut compare` (ขั้นที่ 6) เอา
ไฟล์ที่ทำเสร็จจากขั้นก่อนหน้ามาวางข้างฟุตเทจดิบตามเรขาคณิตที่วัดจากคลิป 06 จริง

## ข้อค้นพบที่ใช้ตั้งค่าได้จริง

### 1 · คัตไม่ได้ล็อกกับบีตเพลง

วัดจังหวะเพลงทั้ง 7 คลิป (72–136 BPM) แล้วเทียบกับเวลาคัตทุกจุด
สัดส่วนคัตที่ตรงบีตอยู่ที่ 4/21 ถึง 8/17 — **เท่ากับหรือต่ำกว่าความน่าจะเป็นโดยบังเอิญ**

คัตเดินตาม**เสียงพากย์** ซึ่งตรงกับวิธีที่ `[jumpcut]` ทำงานพอดี ไม่ต้องไปหาทางตัดตามบีต

### 2 · ห้าในเจ็ดคลิปไม่มีความเงียบเหลือเลย

คลิป 01 · 03 · 04 · 06 พูดต่อเนื่องตั้งแต่วินาทีแรกจนถึงการ์ดปิดท้าย ไม่มีช่องว่างแม้แต่จุดเดียว
แปลว่า **สิ่งที่เห็นคือผลลัพธ์หลังตัดช่องเงียบออกไปแล้ว** ไม่ใช่ของดิบ

คลิป 02 (เงียบ 3 จุด · LRA 16.2) กับ 07 (เงียบ 1 จุด · LRA 9.5) ยังเหลือร่องรอยของกระบวนการ
→ **ใช้สองตัวนี้สอบเทียบ `min_silence` / `pad`** แล้วค่อยเอาค่าไปใช้กับที่เหลือ

### 3 · จังหวะเดินตามหน้าที่ของคลิป ไม่ใช่รสนิยมคงที่

| หน้าที่ | ช็อตเฉลี่ย | ตัวอย่าง |
|---|---|---|
| ปิดการขาย / แนะนำช่อง | 1.7–2.0 วิ | 01 · 02 · 03 |
| โชว์หลักฐาน | 2.4 วิ | 04 |
| สอนกรอบวิธีคิด | **5.0 วิ** | 05 |

และภายในคลิปเดียวยังไม่คงที่ — ทุกคลิปแบบ A ใช้โครง **ช้า → กระจุกถี่ 5–8 ช็อต → ช้า**
ไม่ใช่ความเร็วเดียวตลอด

### 4 · `min_shot` กับ `run_max` ขึ้นกับจำนวนคนในเฟรม

เทียบคลิป 06 กับ 07 ซึ่งเป็นคนเดียวกัน ฟอร์แมตเดียวกัน ห่างกันหนึ่งวัน
ตัวแปรเดียวที่ต่างคือฟุตเทจ:

| | สัมภาษณ์ 2 คน | คนพูดคนเดียว |
|---|---|---|
| ช็อตเฉลี่ย | 1.92 วิ | 2.78 วิ |
| B-roll ติดกัน | 2 ชิ้น | 1 ชิ้น |

ฟุตเทจสองคนต้องตัดถี่กว่าเพราะบทสลับหน้าเร็ว — ไม่ใช่เพราะจะให้ดูเร้าใจกว่า

### 5 · ความดังของต้นฉบับส่วนใหญ่ "ลอกไม่ได้"

ห้าในเจ็ดคลิปอยู่ที่ −9.7 ถึง −10.0 LUFS ซึ่ง**ดังเกินเป้า TikTok (≈−14) ราว 4 dB**
และคลิป 03 กับ 05 มี peak +0.6 dBFS คือ**คลิปแล้ว**

TikTok ปรับความดังขาเข้าอยู่แล้ว ส่งไฟล์ที่ดังกว่านั้นไม่ทำให้ดังขึ้นบนแอป
ได้แค่โดนกดกลับลงมาพร้อมไดนามิกที่เสียไปถาวร

**ตัวที่ลอกได้คือคลิป 04** — −14.7 LUFS · peak 0.0 dBFS ตรงเป้าพอดี

## เริ่มยังไง

```bash
# แบบ B (Before|After) — ตรงกับ vcut ที่สุด เริ่มจากตรงนี้
./vcut run -c vertical-short

# แล้วปรับสามค่าที่วัดมาจากช่อง After ของคลิป 06
./vcut run --set talk.min_shot=1.20 --set broll.run_max=2

# แล้วประกอบเป็นใบเทียบก่อน-หลัง (ขั้นที่ 6)
./vcut compare -c vertical-short \
  --set compare.enabled=true --set compare.before=IMG_1234.mp4 \
  --set compare.title="ฝึกตัดในมือถือ" --set compare.subtitle="Day 1/100"
```

`config/presets/vertical-short.toml` มีค่าพื้นฐานของหนังแนวตั้งอยู่แล้ว
(1080×1920 · jumpcut เปิด · −14 LUFS) — เอกสารรายคลิปบอกว่าต้องปรับอะไรทับบ้าง
