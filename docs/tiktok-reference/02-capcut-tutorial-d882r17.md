## 5 · แปลงเป็น vcut

### ตัวที่เข้าทางที่สุด — ใช้ `vertical-short` ได้เกือบตรง

```bash
./vcut run -c vertical-short
```

ปรับเพิ่มเฉพาะสามค่า ให้ตรงกับความเงียบที่วัดได้จริง (สั้นสุด 0.26 วิ):

```toml
[jumpcut]
enabled     = true
noise_db    = -32.0
min_silence = 0.24     # ต่ำกว่าช่องเงียบที่สั้นที่สุดในต้นฉบับเล็กน้อย
pad         = 0.06
min_piece   = 0.40

[talk]
margin_pre  = 0.15
margin_post = 0.25
gap_merge   = 0.30
min_shot    = 1.00

[broll]
durations = [1.2, 0.8, 0.5]
run_max   = 8          # ต้นฉบับปล่อย B-roll ติดกัน 8 ชิ้น

[compose]
mode           = "pattern"
pattern        = ["TALK", "BROLL", "BROLL"]
target_minutes = 0.60

[audio]
same_level  = false    # คลิปนี้ตั้งใจให้ B-roll เบากว่าเสียงพูด
master_lufs = -14.0
```

### ชั้นขั้น 5

ชุด B-roll ยิงถี่ ใส่ซูมไล่ระดับให้รู้สึกเร่งขึ้น:

```json
{
  "clips": {

    "<คลิป>@15.870+0.900": {"zoom": 1.10, "grade": "punch"},
    "<คลิป>@16.770+1.200": {"zoom": 1.15, "grade": "punch"},

  },

    "duck": true, "duck_db": 6.0, "duck_release": 400,

  }]

```

### ที่ vcut ทำเองไม่ได้

| ของ | ทางออก |
|---|---|
| มาสคอต 3D | **ProRes 4444 (.mov)** ช่องอัลฟา → `overlays` (ไม่ใช่ `.webm`) |
| ทรานสิชันเบลอ+วิป | **ทำได้แล้วแบบประมาณ** — `clips[].whip` เบลอหัว-ท้ายช็อต · ช็อต A ท้ายเบลอ + ช็อต B หัวเบลอ ตาอ่านว่าเป็นรอยต่อเดียว (xfade จริงยังไม่มี) |
| เอฟเฟกต์พิกเซลเลต | เรนเดอร์เป็นคลิปทรานสิชันไว้ก่อน แล้ววางเป็น overlay |

## 6 · ทำไมคลิปนี้ควรเป็นตัวตั้งต้น

อีก 6 คลิปถูกอัดเสียงจนแบน (LRA 2.3–9.5) และไม่มีความเงียบให้ตัดเลย — แปลว่าคนทำ**ตัดช่องว่างออกไปแล้วด้วยมือ** ก่อนอัดเสียง สิ่งที่เห็นจึงเป็นผลลัพธ์ ไม่ใช่กระบวนการ

คลิปนี้ยังเหลือร่องรอยของกระบวนการอยู่ (เงียบ 0.26–0.49 วิ คั่น 3 จุด) ซึ่งคือ**ของดิบที่ `[jumpcut]` กินได้พอดี** ถ้าจะสอบเทียบค่า `min_silence` / `pad` ให้ใช้คลิปนี้เป็นตัววัด แล้วค่อยเอาค่าที่ได้ไปใช้กับคลิปอื่น
