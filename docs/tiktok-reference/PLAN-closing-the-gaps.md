## ทำไมของส่วนใหญ่ถูกกว่าที่คิด

โครงของขั้น 5 ทำให้การเพิ่มเอฟเฟกต์รายช็อต**เกือบไม่มีค่าใช้จ่ายทางสถาปัตยกรรม** เพราะสองอย่าง:

### 1 · ท้ายสายของ `seg_vfilter()` กันความยาวเพี้ยนให้แล้ว

```python
parts.append("tpad=stop_mode=clone:stop_duration=0.5")
parts.append(f"fps={ctx.get('video.fps', ...)}")
parts.append(f"trim=end_frame={int(frames)}")
```

สามบรรทัดนี้บังคับให้ชิ้นออกมา `frames` เฟรมพอดี**ไม่ว่าจะเอาอะไรไปต่อข้างหน้า** —
ยืนยันแล้วด้วย `zoompan` (ซึ่งขึ้นชื่อเรื่องทำจำนวนเฟรมเพี้ยน) ได้ 90/90 เฟรม

แปลว่าฟิลเตอร์ใหม่ทุกตัวแทรกได้เลยโดยไม่ต้องคิดเรื่องเสียงกับภาพหลุด sync

### 2 · `seg_key()` แฮชสตริงฟิลเตอร์ ระบบ cache จึงถูกต้องเอง

```python
return key_of({... "vf": seg_vfilter(f, ctx, frames), ...})
```

เพิ่มช่องใหม่ใน `fx.CLIP` แล้วเขียนโค้ดต่อฟิลเตอร์ใน `seg_vfilter()` →
กุญแจเปลี่ยนเองเมื่อค่าเปลี่ยน · ไม่เปลี่ยนเมื่อค่าไม่เปลี่ยน
**ไม่ต้องแตะโค้ด cache เลยแม้แต่บรรทัดเดียว**

และ `_pick()` ใน `fx.merge()` ดัดค่าให้อยู่ในช่วงให้อยู่แล้ว แค่เพิ่มชื่อคีย์ลง `LIMITS`

> นี่คือเหตุผลที่ข้อ 2 · 3 · 4 อยู่ในระดับ "เล็ก" ทั้งที่ฟังดูเหมือนงานใหญ่

## รอบ 2 — ทำเสร็จแล้ว

เพิ่มห้าช่องใน `fx.CLIP` ซึ่งทำให้ทั้งสามข้อใช้งานได้ทั้งจาก `fx.json` และจากหน้าเว็บ:

| ช่อง | ค่าตั้งต้น | ความหมาย |
|---|---|---|
| `zoom_to` | `0.0` | ซูมปลายทาง · **0 = ไม่เดิน** (ซูมค้างเหมือนเดิม) |
| `pan` | `""` | `l` `r` `u` `d` — ทิศที่กรอบภาพไถล · ต้องมี `zoom > 1` |
| `glitch` | `0.0` | ภาพกระตุก 0–1 |
| `glitch_hz` | `1.4` | กระตุกกี่ครั้ง/วินาที (มีผลเมื่อ `glitch > 0`) |
| `whip` | `0.0` | เบลอหัว-ท้ายช็อต 0–1 |

```json
{
  "clips": {
    "CLIP@0.000+2.000": {"zoom": 1.0, "zoom_to": 1.5, "pan": "r"},
    "CLIP@2.000+1.400": {"glitch": 0.7, "glitch_hz": 4.0, "whip": 0.5}
  }
}
```

ฝั่งหน้าเว็บ: แผง **เอฟเฟกต์ (ขั้น 5)** ใน `Properties.tsx` มีช่อง "ซูมเริ่ม / ซูมจบ /
ไถลกรอบภาพ / กระตุก / เบลอหัว-ท้าย" และจอตัวอย่างวาดทั้งสามชั้นสด — กล้องเคลื่อนด้วย
`transform` · กระตุกด้วยฟิลเตอร์ SVG ที่แยกช่องสีจริงแบบเดียวกับ `rgbashift`
(ไม่ใช่ `drop-shadow` ซึ่งวาดเงาสีทับ) · เบลอด้วย `blur()` ที่ย่อตามขนาดจอตัวอย่าง

### 🐛 กับดักที่เจอตอนลงมือ — zoompan ลบผลของ speed ทิ้งเงียบ ๆ

ร่างเดิมของเอกสารนี้ (ข้อ 2 ข้างล่าง) เขียนให้วาง `zoompan` **หลัง** `setpts` ซึ่ง**ผิด**

`zoompan` สร้างไทม์ไลน์ของตัวเองที่อัตรา `fps` แล้ว**ทิ้ง PTS ขาเข้า** ผลคือมันลบสิ่งที่
`setpts` เพิ่งทำไปทั้งหมด วัดจริง: ช็อต 90 เฟรมตั้ง `speed = 2`

| | ควรได้ | ได้จริง (zoompan หลัง setpts) |
|---|---|---|
| จำนวนเฟรม | 45 | 45 ✅ |
| เนื้อหา | เฟรม 0–89 ย่อลง | **เฟรม 0–44 ที่ความเร็วปกติ** ❌ |

**ครึ่งหลังของช็อตหายไปโดยไม่มีอะไรฟ้อง** — จำนวนเฟรมยังถูกต้องเพราะท้ายสาย
`trim=end_frame` ตัดให้ ด่านความยาวที่มีอยู่จึงจับไม่ได้เลย

แก้โดยวาง `zoompan` **ก่อน** `setpts` และใช้จำนวนเฟรม *ขาเข้า* (`frames × speed`)
เป็นตัวหารความคืบหน้า ไม่ใช่เฟรมขาออก

มีด่านกันไว้แล้วที่ [`scripts/check_clip_fx.py`](../../scripts/check_clip_fx.py) —
สลับลำดับกลับเมื่อไรมันจะฟ้องทันทีพร้อมบอกวิธีแก้ (ทดสอบด่านด้วยการใส่บั๊กกลับเข้าไปจริง)

### ค่าที่เป็นพารามิเตอร์ของเอฟเฟกต์อื่น

`glitch_hz` ตอน `glitch` ปิด และ `pan` ตอนไม่ได้ซูม **ไม่มีผลกับภาพเลย** ถ้า `touched()`
นับว่า "ถูกแตะ" ชิ้นนั้นจะถูกดึงออกจากไฟล์ของขั้น 3 มาเข้ารหัสใหม่ทั้งชิ้นแล้วได้ผล
เหมือนเดิมเป๊ะ — เสียเวลาฟรีโดยไม่มีใครสั่ง

แก้ด้วยตาราง `fx.SUBORDINATE` ที่บอกว่าค่าไหนขึ้นกับค่าไหน แล้ว `touched()` ข้ามให้

## รอบ 3 — ทำเสร็จแล้ว

### ข้อความที่โผล่ทีละคำ

`ANIM` เพิ่มสองแบบ: **`fade_words`** (โผล่ทีละคำ) กับ **`pop_words`** (เด้งทีละคำ)
ทำในบรรทัดเดียวโดยแทรกแท็กคั่นกลาง ให้ libass จัดวางเอง — ไม่ต้องวางข้อความหลายชิ้น
แล้วลากจัดตำแหน่งทีละคำ

```
{\alpha&HFF&\t(0,220,\alpha&H00&)}คลิป {\alpha&HFF&\t(121,341,\alpha&H00&)}VDO …
```

**วัดจริงบนจอ 1080 ว่าบรรทัดที่จัดกลางไหลแค่ไหน** (เพราะการย่อ-ขยายตัวอักษรกลางบรรทัด
ทำให้ความกว้างรวมเปลี่ยน แล้วบรรทัดจัดกลางเลื่อนทั้งแถบ):

| วิธี | ขอบซ้ายไหล | ใช้ได้ไหม |
|---|---|---|
| `fade_words` (แตะแค่ความทึบ) | **0 พิกเซล** | ✅ นิ่งสนิท |
| เด้งโดยย่อจาก 58% ก่อน | **90 พิกเซล** | ❌ อ่านว่าภาพสั่น |
| เด้ง 100 → 112 → 100 | **~15 พิกเซล** | ✅ อ่านว่าเป็นจังหวะเด้ง |

จึงเลือกแบบที่สาม — คำที่ยังไม่ถึงคิวกินที่เท่าเดิม (มองไม่เห็นแต่กว้างเท่าเดิม)

> ภาษาไทยไม่เว้นวรรคระหว่างคำ จึงไล่ได้เฉพาะที่คนพิมพ์เคาะเว้นวรรคเอง ซึ่ง**ตรงกับ
> ที่ต้นฉบับทำอยู่แล้ว** (คลิป 01: "คลิป VDO ของคุณ" เว้นวรรคพอดีสามช่วง) —
> ลากตัวตัดคำไทยเข้ามาจะเพิ่ม dependency ใหญ่เพื่อผลที่คนทำคุมเองได้ด้วยการเคาะเว้นวรรค

### ตัวเลขที่นับขึ้น

`TEXT_ITEM` เพิ่ม `count` (`int` · `comma` · `k` · `pct` · `1dp`) กับ `count_from` / `count_to`
เลขไปแทนที่ `{n}` ในข้อความ · ไม่มี `{n}` = เลขแทนข้อความทั้งก้อน

ASS ไล่ค่าให้ได้เฉพาะ *ตัวเลขในแท็ก* ไม่ใช่ตัวหนังสือ — ชิ้นหนึ่งจึงถูกซอยเป็นหลาย
`Dialogue` ก้าวละ 1/12 วินาที ชะลอตอนท้ายด้วย `1−(1−p)³` แล้วยุบก้าวที่ได้ข้อความ
เท่ากันเข้าด้วยกัน

```json
{"texts": [{
  "name": "<คลิป>", "at": 0.0, "dur": 2.4, "anim": "fade",
  "count": "k", "count_from": 0, "count_to": 255900,
  "lines": [{"text": "ยอดเข้าชมวิดีโอ", "size": 44},
            {"text": "{n}", "size": 150, "gap": 0.18}]
}]}
```

เรนเดอร์ออกมาได้ 24.7K → 89.3K → 190.9K → 255.9K โดยป้ายด้านบนอยู่นิ่ง

### 🐛 สองบั๊กที่เจอตอนลงมือ

**1 · แท็ก ASS ถูกกลืนเป็นอักขระควบคุม**

เขียน `\alpha` กับ `\t` ในสตริง Python ที่ไม่ใช่ raw string → กลายเป็น BEL กับ TAB
libass เจอ `{lpha&HFF&` แล้ว**ทิ้งทั้งบล็อกโดยไม่บ่นอะไร** ข้อความยังขึ้นครบทุกคำ
แค่ไม่มีแอนิเมชันเลย — ไม่มีทางรู้ถ้าไม่เปิดไฟล์ ASS อ่าน

**2 · การ์ดหลายบรรทัดกลายเป็นตัวเลขทั้งใบ**

กฎ "ไม่มี `{n}` = เลขแทนข้อความทั้งก้อน" พอเอาไปใช้กับการ์ด ทำให้บรรทัด
"เวลาที่ดูโดยเฉลี่ย" กลายเป็น "0.0" ไปด้วย  แก้เป็น **การ์ดต้องมี `{n}` ชัด ๆ**
และบรรทัดที่ไม่มีถูกปล่อยครั้งเดียวยาวทั้งชิ้น ไม่ใช่ซ้ำเท่าจำนวนก้าว
(การ์ดหนึ่งใบลดจาก 48 บรรทัดเหลือ 25)

### ที่ตรวจแล้ว

| | ผล |
|---|---|
| ไฟล์ ASS ของค่าเดิม 60 ชุด เทียบกับโค้ดก่อนแก้ | **เหมือนเดิมทุกตัวอักษร** |
| รูปแบบตัวเลข หน้าเว็บ vs เอนจิน 205 กรณี | ตรงกันหมด (รวมค่าที่ตกครึ่งพอดี เช่น 1250 → `1.2K`) |
| จังหวะไล่ทีละคำ หน้าเว็บ vs เอนจิน 64 กรณี | ตรงกันหมด |
| เรนเดอร์ผ่าน libass จริง | คำโผล่ทีละคำถูกลำดับ · เลขไล่ถึง 255.9K แล้วจางออก |
| จอตัวอย่างสด | เลขเดินตามหัวเล่น (93.0K ที่ 13.0 วิ → 255.9K ที่ 14.5 วิ) |
| `tsc` · `next build` · eslint | ผ่าน · ผ่าน · 17 ปัญหา (เท่าเดิม) |

## รอบ 4 — ทำเสร็จแล้ว · เส้นนีออนเรืองแสง

### สิ่งแรกที่ตรวจ: libass รองรับ `\blur` จริงไหม

รองรับ — วัดจากภาพที่เรนเดอร์จริง ไม่ใช่จากคู่มือ: แถบที่สั่ง `\blur12` มีขอบ
ไล่จาก 42 ถึง 223 ตลอด 25 พิกเซล ส่วนแถบ `\blur0` กระโดด 0 → 252 ในพิกเซลเดียว

### วาดซ้ำสามชั้น แต่ใช้สตริงรูปเดิม

เอกสารร่างเดิมเสนอให้ "วาดเส้นเดิมซ้อนกันสามชั้นที่ความหนา ×3.0 / ×1.8 / ×1.0"
ซึ่งแปลว่าต้องเรียก `stroke()` ใหม่ทุกชั้น แล้วสตริงเส้นทาง (ซึ่งของแผนที่ยาว
เป็นพันตัวอักษร) บวมสามเท่าจริง ๆ

**ทางที่ถูกกว่า: ขยายด้วย `\bord` แล้วละลายขอบด้วย `\blur`** — ได้ผลเดียวกัน
โดยใช้สตริงรูป *เดิม* ซ้ำได้ทั้งสามชั้น

| ชั้น | `\bord` | `\blur` | ความทึบ | สี |
|---|---|---|---|---|
| ฮาโลกว้าง | 2.6 × unit | 2.0 × unit | 60% | สีของเส้น |
| ฮาโลแคบ | 1.1 × unit | 0.8 × unit | 35% | สีของเส้น |
| แกน | 0 | 0.22 × unit (แผนที่) · 0 (รูปทรง) | 100% | ขาว |

สองชั้น ไม่ใช่ชั้นเดียว เพราะแสงจริงมีทั้งฮาโลกว้างจาง ๆ กับวงในสว่างชิดตัว —
ชั้นเดียวได้ขอบฟุ้งเท่ากันทั้งวง ตาอ่านว่า "เบลอ" ไม่ใช่ "เรืองแสง"

ตัววาดอยู่ที่ [`journey.glow_layers()`](../../vcut_engine/journey.py) ที่เดียว
ทั้งเส้นแผนที่กับรูปทรงเรียกตัวเดียวกัน — ชิปในผังนีออนจึงหน้าตาเป็นชุดเดียวกับ
เส้นที่ลากถึงมันโดยไม่ต้องจูนสองที่

### 🐛 กับดักที่เจอตอนลงมือ — ฮาโลไม่มีเพดาน

ให้ฮาโลโตตามความหนาของของแบบตรงไปตรงมา (`unit = ความหนา`) แล้วชิปสี่เหลี่ยมมนที่
หนา 57 พิกเซลได้ฮาโลกว้าง **148 พิกเซล** ซึ่งท่วมทั้งเฟรมจนอ่านไม่ออกว่ามีรูป

หลอดนีออนจริงที่อ้วนขึ้นสองเท่าไม่ได้มีแสงฟุ้งกว้างขึ้นสองเท่า — ความกว้างของ

## รอบ 6 — ทำเสร็จแล้ว · แบ่งจอสองคน

```json
{"clips": {"CLIP@0.000+4.000": {
  "split": "v", "split_with": "IMG_7420.mp4", "split_at": 12.5}}}
```

**อีกครึ่งดึงจากฟุตเทจดิบ ไม่ใช่จากไทม์ไลน์** — ช่วงที่อยากเอามาเทียบมักเป็นช่วง
ที่ *ถูกตัดทิ้งไปแล้ว* (นั่นคือเหตุผลที่อยากเทียบ) ถ้าให้เลือกได้เฉพาะชิ้นที่อยู่
ในไทม์ไลน์ก็จะเลือกไม่ได้เลย

### ประกอบภาพก่อน แล้วเอาสายเดิมทั้งเส้นไปต่อท้าย

```
[0:v] ย่อ+ครอบเป็นครึ่งจอ ──┐
                            ├─ vstack ──▶ [สายฟิลเตอร์เดิมทั้งเส้น] ──▶ [v]
[1:v] ย่อ+ครอบเป็นครึ่งจอ ──┘
[0:a] ──────────────────────────────────────────────────────────────▶ [a]
```

ทำแบบนี้แล้ว**ทุกอย่างที่ขั้น 5 ทำได้อยู่แล้วยังทำงานกับชิ้นที่แบ่งจอได้ครบ** —
สโลว์โม · ซูม · กล้องเคลื่อน · โทนสี · กระตุก · เบลอหัว-ท้าย — โดยไม่ต้องเขียนใหม่
สักตัว และท้ายสายที่บังคับจำนวนเฟรมก็ยังเป็นตัวเดิม ความยาวจึงเป๊ะเท่าเดิม

### 🐛 สองเรื่องที่เจอตอนลงมือ

**1 · คีย์ที่ค่าเป็นค่าว่างก็ทิ้ง cache ทั้งกองได้**

`seg_key()` ทำ `json.dumps` ทั้งก้อนแล้วแฮช — ใส่ `"src2": ""` ไว้เสมอ (แม้ไม่ได้
แบ่งจอ) ก็เปลี่ยนสตริงที่เอาไปแฮช ผลคือ**ชิ้นทุกชิ้นของทุกโปรเจกต์ที่มีอยู่ได้กุญแจ
ใหม่พร้อมกัน** แล้ว cache ทั้งกองถูกทิ้งตอนอัปเดตเอนจิน โดยที่ไม่มีใครตั้งอะไรใหม่
เลยสักค่า  แก้เป็นใส่คีย์พวกนี้เฉพาะตอนแบ่งจอจริง

**2 · `tpad` ที่ผมใส่ไว้ "กัน" ไม่ได้ทำอะไรเลย และคอมเมนต์ที่อธิบายมันก็ผิด**

ร่างแรกใส่ `tpad=stop_mode=clone` ที่ทั้งสองครึ่ง พร้อมคอมเมนต์ว่า "vstack จบทันที
ที่อินพุตไหนหมดก่อน ถ้าไม่เติมให้ยาวพอ ชิ้นทั้งชิ้นจะถูกตัดสั้น" — และคำนวณความยาว
ที่ต้องเติมจากเวลา *ขาเข้า* อย่างระมัดระวังเพราะกลัวบั๊กพี่น้องกับที่ `zoompan` เคยทำ

ตอนทดสอบด่านด้วยการใส่บั๊กกลับเข้าไป (เปลี่ยนให้คิดจากเวลาขาออก) **ด่านไม่ฟ้อง** —
ไล่ต่อถึงรู้ว่าค่าตั้งต้นของ `vstack` คือ **ซ้ำเฟรมสุดท้ายของฝั่งที่หมดก่อนอยู่แล้ว**
วัดจริง: อินพุต 8 วิ + 2 วิ ได้ 240 เฟรมเท่ากันทั้งมีและไม่มี `tpad`

ถอด `tpad` ออกทั้งสองครึ่ง แล้วเขียน `shortest=0` ไว้ที่ `vstack` ตรง ๆ แทน —
สั้นกว่า ตรงกว่า และบอกว่านี่คือ *การตัดสินใจ* ไม่ใช่การไม่ได้ตัดสินใจ

> บทเรียนที่ใช้ซ้ำได้: **ด่านที่ไม่ฟ้องตอนใส่บั๊กกลับ อาจแปลว่าโค้ดที่ "แก้บั๊ก"
> นั้นไม่ได้แก้อะไรเลย** ไม่ใช่แปลว่าด่านอ่อน — ตรวจสมมติฐานก่อนไปเสริมด่าน

### 1 · glitch / RGB แยกช่อง 🟢 ✅ ทำแล้ว

**ที่แก้:** `fx.CLIP` + `fx.LIMITS` + `fx.seg_vfilter()`

```python
# fx.py — เพิ่มใน CLIP
CLIP = {
    ...,
    "glitch": 0.0,        # ความแรง 0 = ปิด · 1 = แรงสุด
    "glitch_hz": 1.4,     # กระตุกกี่ครั้งต่อวินาที
}

# LIMITS
"glitch": (0.0, 1.0), "glitch_hz": (0.2, 12.0),
```

```python
# seg_vfilter() — ใส่ *ก่อน* tpad เสมอ (ท้ายสายห้ามแตะ)
gl = float(f.get("glitch", 0.0) or 0.0)
if gl > 1e-6:
    hz = float(f.get("glitch_hz", 1.4) or 1.4)
    period = 1.0 / hz
    on = min(0.10, period * 0.28)          # ติดสั้น ๆ ไม่งั้นอ่านว่าภาพเสีย
    shift = int(round(28 * gl))
    gate = f"lt(mod(t\\,{period:.4f})\\,{on:.4f})"
    parts.append(f"rgbashift=rh=-{shift}:bh={shift}:enable='{gate}'")
    if gl > 0.45:                          # แรงมากค่อยใส่ noise เพิ่ม
        n = int(round(60 * gl))
        parts.append(f"noise=alls={n}:allf=t+u:enable='{gate}'")
```

**ทดสอบแล้ว:** เฟรมครบ 90/90 · `enable` ติด-ปิดตรงเวลาที่สั่ง

> คอมมาในสูตร `enable` ต้อง escape เป็น `\,` ไม่งั้นถูกอ่านเป็นตัวคั่นฟิลเตอร์ —

สามทางที่เป็นไปได้:

| ทาง | ผล |
|---|---|
| เปลี่ยนเป็น N `-i` แล้วต่อ `xfade` เป็นลูกโซ่ | โปรเจกต์ 208 ช็อตกลายเป็น 208 อินพุตในคำสั่งเดียว — ชนเพดาน ffmpeg และช้ามาก **ไม่แนะนำ** |

| ทำเป็นขั้นแยกหลัง concat | ต้องเข้ารหัสซ้ำอีกรอบ ขัดกับหลัก "พาสเดียว" ที่ `finish.py` ตั้งใจไว้ |

**คำแนะนำ: ทำแบบประมาณก่อน แล้ววัดว่ายังไม่พอจริงไหมค่อยลงทุนกับ xfade**

### 4 · ตัวหนังสือเด้งทีละคำ 🟡 ✅ ทำแล้ว

เอกสารเดิมแนะนำให้ "แยกเป็นข้อความหลายชิ้นเหลื่อม `at` ทีละ 0.08 วิ" —
ใช้ได้แต่แย่ เพราะต้องจัดตำแหน่งเองทุกคำ และพอแก้ข้อความทีเดียวต้องลากใหม่หมด

**ทางที่ถูกกว่า: ทำในบรรทัดเดียว ให้ libass จัดตำแหน่งเอง**

ASS รับแท็กกลางบรรทัดได้ และ `\t` ทำงานแยกกันต่อช่วง:

```
{\fscx58\fscy58\alpha&HFF&\t(0,90,\fscx100\fscy100\alpha&H00&)}คลิป
{\fscx58\fscy58\alpha&HFF&\t(80,170,\fscx100\fscy100\alpha&H00&)}VDO
{\fscx58\fscy58\alpha&HFF&\t(160,250,\fscx100\fscy100\alpha&H00&)}ของคุณ
```

**ที่แก้:** `fxtext.anim_tags()` เพิ่มชนิด `pop_words` / `fade_words`

```python
# fx.py
ANIM = {..., "pop_words": "เด้งเข้ามาทีละคำ"}

# fxtext.py — ตัวประกอบข้อความ ไม่ใช่ตัวประกอบแท็ก
def stagger_words(text, ti, step=80):
    """แตกข้อความเป็นคำแล้วให้แต่ละคำเด้งเหลื่อมกัน — คืนสตริง ASS ทั้งบรรทัด"""
    out = []
    for i, w in enumerate(text.split(" ")):
        a = i * step
        b = a + max(60, ti)
        out.append(rf"{{\fscx58\fscy58\alpha&HFF&"
                   rf"\t({a},{b},\fscx100\fscy100\alpha&H00&)}}{w}")
    return " ".join(out)
```

> **ข้อจำกัดที่ต้องบอกคนใช้:** ภาษาไทยไม่เว้นวรรคระหว่างคำ `text.split(" ")` จึงแตกได้
> เฉพาะที่คนพิมพ์เว้นวรรคเอง ซึ่ง**ตรงกับที่ต้นฉบับทำอยู่แล้ว** (ดูคลิป 01: "คลิป VDO ของคุณ"
> เว้นวรรคสามช่วงพอดี) การเรียกตัวตัดคำไทยมาที่นี่จะเพิ่ม dependency ใหญ่เพื่อผลที่คนทำ
> คุมเองได้อยู่แล้วด้วยการเคาะเว้นวรรค

### 5 · ตัวเลขนับขึ้น 🟡 ✅ ทำแล้ว

`\t` ของ ASS interpolate ได้แค่ค่าที่เป็นตัวเลขของ *แท็ก* ไม่ใช่ *เนื้อข้อความ*

    p  = i / (steps - 1)

   `drawtext`** (ยืนยันแล้ว) ตัวที่มีคือ `/opt/homebrew/opt/ffmpeg-full/bin/ffmpeg`
   เขียนโค้ดเรียก `ffmpeg` ตรง ๆ จะพังเฉพาะบนเครื่องที่ไม่มี ffmpeg-full ซึ่งเป็นบั๊ก
   ที่ไม่โผล่ตอนเทสต์บนเครื่องคนเขียน
2. **ความยาวสองเรื่องไม่เท่ากัน** — After สั้นกว่า Before เสมอ (นั่นคือประเด็นของคลิป)
   ต้องตัดสินใจว่าจะให้ Before เล่นต่อไปเงียบ ๆ หรือหยุดค้าง · `shortest=1` ตัดที่ตัวสั้นสุด
   ซึ่ง**ไม่ใช่สิ่งที่ต้องการ** เพราะจะตัด Before ทิ้งกลางคัน
3. **เสียงเอาจากฝั่ง After อย่างเดียว** — ผสมสองฝั่งจะได้เสียงซ้อนที่ฟังไม่รู้เรื่อง

**ของแถม:** แถบไทม์ไลน์ CapCut ด้านล่างจำลองได้ไม่ยากถ้าอยากทำ — เอา `thumbs.py` ที่มีอยู่
มาทำแถบภาพย่อย แล้ววาดคลื่นเสียงด้วย `showwaves` กับหัวเล่นด้วย `drawbox` ที่ `x='t/DUR*W'`
แต่**ยังไม่แนะนำ** จนกว่าตัวเลย์เอาต์หลักจะใช้งานได้จริงก่อน

### ที่ยังไม่ได้ทำ (และไม่เคยอยู่ในตารางช่องว่าง)

- **xfade แบบจริง** (ข้อ 3 ครึ่งหลัง) — ต้องแก้ `fx.plan()` ให้รู้จักชิ้นที่กินสองช็อต
  และ remap เวลาของข้อความ/รูปทรงทั้งขั้น 5 · แบบประมาณ (`whip`) ยังพอใช้อยู่

  มาวางเป็นแถบล่างได้ (`compare.timeline`) แต่ยังไม่ได้จำลองแถบขึ้นมาเองจาก
  `thumbs.py` + `showwaves` ตามที่ร่างไว้ในข้อ 8
- **พรีวิวสดของแผนที่กับของอีกครึ่งจอ** — จอตัวอย่างบอกตรง ๆ ว่ายังไม่วาดให้
