[tiktok-reference](tiktok-reference/README.md) → เอนจินตัดให้เอง 2–5 แบบ → คนเลือก"**

ตัวเลขทุกตัวในเอกสารนี้**มาจากการรันจริง**กับ `excemple-video-cut.mov` (134.5 วิ ·

| `listen` | **38.8 วิ** | 26 ท่อน · พูด 1.7 จาก 2.2 นาที |

| `prepare` + `compose` | < 0.1 วิ | (ดูข้อ G1) |

| `assemble` | 4.3 วิ | 1080×1920 · 59.94 fps · **−14.1 LUFS** (จาก −6.8) |
| **รวมครั้งแรก** | **~80 วิ** | |

> `listen` คือคอขวด (ครึ่งหนึ่งของเวลาทั้งหมด) แต่ทำครั้งเดียวต่อคลิป — ทุกแบบใช้ transcript ร่วมกัน

### G1 · คลิปเดียวกลายเป็นชิ้นเดียว แล้วย่อไม่ได้

whisper คืน 26 ท่อนที่**ต่อกันสนิทไม่มีช่องว่าง** (0–3 · 3–4 · 4–6 · … · 94–101) →
`talk_ranges()` ใน [prepare.py:25](../vcut_engine/prepare.py#L25) เชื่อมเป็นช่วงเดียว 0–101.25 วิ
ไม่ว่าจะตั้ง `gap_merge` ต่ำแค่ไหน (ทดสอบ 0.40 / 0.15 / 0.05 → ได้ 2 ชิ้นเท่ากันทุกค่า)

จากนั้นทุกโหมดของ [compose.py](../vcut_engine/compose.py) **หยิบชิ้นทั้งชิ้นหรือไม่หยิบเลย**:

| โหมด | ตั้ง | ได้ |
|---|---|---|
| `all` | — | 2 ชิ้น · 1.7 นาที (= ทั้งคลิปลบท่อนไม่มีเสียงพูด) |
| `pattern` (ค่าใน `vertical-short`) | เป้า 0.75 นาที | **0 ชิ้น** — ชิ้นแรก 101 วิ > เป้า 45 วิ → `break` ทันที ([compose.py:229](../vcut_engine/compose.py#L229)) |
| `budget` | พูด 0.75 นาที | **0 ชิ้น** — ชิ้น 101 วิ ไม่พอดีงบ ข้ามไป ([compose.py:270](../vcut_engine/compose.py#L270)) |

นี่คือสาเหตุที่ `./vcut run -c vertical-short` กับคลิปเดียว**ได้หนังเปล่า** — เอนจินถูกออกแบบ
มาสำหรับกองคลิปสั้น ๆ 273 อัน ไม่ใช่คลิปเดียวยาว 2 นาที ซึ่งเป็นโจทย์คนละแบบ

### G2 · เกณฑ์เงียบคงที่ใช้กับ TikTok ไม่ได้

คลิปตัวอย่างมีเพลงคลอตลอดและดัง −6.8 LUFS (เหมือน 5 ใน 7 คลิปอ้างอิงที่ −10 LUFS)
`silencedetect` ที่ −32 dB จึงไม่เจออะไรเลย ต้องขยับขึ้นมาถึง −15 dB ถึงเจอ 7 ช่วง:

```
noise=-32dB → 0 ช่วง     noise=-22dB → 1     noise=-18dB → 3     noise=-15dB → 7
```

พอตั้ง `jumpcut.noise_db=-15` prepare ซอยเป็น 6 ชิ้น (53.8 · 28.0 · 5.4 · 10.8 · 2.2 · 2.4 วิ)
ซึ่งพอใช้ตัดชนได้ แต่ค่านี้**ขึ้นกับความดังของแต่ละคลิป** — ต้องคำนวณเอง ไม่ใช่ค่าคงที่

### สิ่งที่ทำงานดีอยู่แล้ว (ไม่ต้องแตะ)

- โฟลเดอร์ที่มีไฟล์เดียว → ทุกขั้นวิ่งปกติ ไม่มีข้อผิดพลาด
- 1126×1788 HEVC 60 fps VFR → ออกมา 1080×1920 h264 59.94 CFR พื้นเบลอ (`blur_pad`) ถูกต้อง
- ความดัง −6.8 LUFS ถูกดึงลง −14.1 LUFS ตามเป้าแพลตฟอร์ม (ตรงกับข้อค้นพบ 5 ใน README อ้างอิง)
- `assemble -o ชื่ออื่น.mp4` จาก cache = 4 วิ → **แบบที่ 2–5 ราคาถูกมากตราบใดที่ชิ้นซ้ำกัน**
- `settings.estimate()` ([settings.py:1080](../vcut_engine/settings.py#L1080)) ตอบได้ว่า config ชุดนี้จะได้กี่ชิ้น ยาวเท่าไร ต้อง render กี่ชิ้น **โดยไม่เรียก ffmpeg** — ใช้คัดว่าแบบไหนคุ้มก่อนตัดจริง

## 3 · สิ่งที่ "สไตล์ TikTok" ต้องมี และเอนจินมีอะไรบ้าง

จาก [tiktok-reference](tiktok-reference/README.md) สไตล์หนึ่งประกอบด้วยสองชั้น:

### ชั้นตัด (preset `.toml`) — มีกลไกครบ ขาดแค่ไฟล์

| สไตล์ (จากคลิปอ้างอิง) | ช็อตเฉลี่ย | ค่าหลักที่ต่าง | สถานะ |
|---|---|---|---|
| ปิดการขาย / แนะนำช่อง (01 · 02 · 03) | 1.7–2.0 วิ | `min_shot` 0.5–1.0 · `run_max` 5–8 · เป้า 0.55–0.70 นาที | ค่าอยู่ในเอกสาร ยังไม่เป็นไฟล์ preset |
| โชว์หลักฐาน (04) | 2.4 วิ | `min_shot` 1.0 · `run_max` 7 · เป้า 0.72 | เหมือนกัน |
| สอนกรอบวิธีคิด (05) | 5.0 วิ | `min_shot` 2.0 · `gap_merge` 0.60 · `pattern` TALK,TALK,BROLL · เป้า 1.9 | เหมือนกัน |
| Before\|After (06 · 07) | 1.9–2.8 วิ | `min_shot` 1.2 · `run_max` 2 · **+ `vcut compare`** | ⚠️ `compare` ถูกลบไปแล้วใน a5c1323 — README อ้างอิงยังพูดถึงอยู่ |

→ งานคือเขียน preset 3–4 ไฟล์ใน `config/presets/` (คัดลอกจากหัวข้อ "แปลงเป็น vcut"
ของแต่ละคลิป) แล้วเพิ่มลง `RECIPES` ใน [settings.py:866](../vcut_engine/settings.py#L866)
ให้หน้าเว็บมีปุ่ม — **ครึ่งวัน**

### ชั้นหน้าตา (`fx.json`) — ฟีเจอร์ครบ 9/9 แต่ยังไม่มี "แม่แบบ"

ทุกอย่างในตาราง "สิ่งที่ต้นฉบับทำแล้วเอนจินต้องตามให้ทัน" ทำครบแล้ว (glitch · ซูมเคลื่อน ·
ตัวหนังสือทีละคำ · เลขนับ · นีออน · แบ่งจอ · โทนสี 5 แบบใน `fx.GRADE`) **แต่ทั้งหมดต้องมีคน
ระบุเป็นราย (คลิป, วินาที)** ใน `fx.json` — ไม่มีตัวที่ดู EDL แล้ววางให้เอง

"ตัดให้เลย" ต้องมี **`autofx`** — กฎง่าย ๆ ที่แปลงสไตล์เป็น fx.json จาก EDL ที่เพิ่งได้:

| กฎ | ทำจากอะไร |
|---|---|
| ช็อตแรก = HOOK → การ์ด 3 บรรทัด `pop_words` เน้นคำแดง `#E0102A` | ข้อความจาก transcript ของชิ้นแรก · สไตล์จากคลิป 01 |
| ชิ้นที่สั้นกว่า 1 วิ ติดกัน ≥ 3 ชิ้น = "ชุดยิงรัว" → `zoom` ไล่ 1.05→1.22 + `grade: punch` | คลิป 02 · 04 |
| ชิ้นสุดท้าย → การ์ดปิด 4.0 วิ (ชื่อช่อง) | ทุกคลิปอ้างอิง |
| ซับอัตโนมัติจาก transcript (ขั้น 4 มี `auto.enabled` อยู่แล้ว) | [caption.py:256](../vcut_engine/caption.py#L256) |
| เพลงคลอจากคลัง 53 ลูป + duck | `music` ในขั้น 5 |

โมดูลใหม่ ~150 บรรทัด อ่าน `edl.json` + `transcript.json` + ชื่อสไตล์ → เขียน `fx.json`
ราคาที่ต้องจ่ายคือขั้น 5 เข้ารหัสทั้งเรื่องใหม่ (≈ 1× ความยาว)

## 5 · AI ช่วยได้ตรงไหน — และผลทดลอง

`vcut ai --task trim_suggest` มีอยู่แล้ว ([ai.py:397](../vcut_engine/ai.py#L397)) รับโจทย์
ภาษาไทย ดูคำพูดพร้อมเวลา แล้วตอบ `keep: [[a, b], …]` หลายช่วงต่อคลิป → `prepare.py`
เอาไป `intersect()` กับช่วงพูด → **ได้หลายชิ้นจากคลิปเดียว** ซึ่งเป็นสิ่งที่กฎล้วนทำไม่ได้ (G1)

ผลรันจริงกับคลิปตัวอย่าง (`--model sonnet` ผ่าน `claude -p` · โจทย์ "ตัดเหลือ 40–45 วิ
เอา hook + จุดสำคัญ 3–4 จุด + ประโยคปิด"):

| | ผล |
|---|---|
| เวลา | `trim_suggest` 140 วิ + `shot_scoring` 68 วิ = **3.5 นาที** (นานกว่าตัดทั้งหมดรวมกัน 2.5 เท่า) |
| ค่าใช้จ่าย | $0.39 + $0.16 = **$0.54 ต่อคลิป** |
| คำตอบ | `keep = [[0, 18], [53, 66], [87, 101]]` · เหตุผล "Hook 0–11 วิ เปิดเรื่องแข็ง … + ถามแล้วตอบ" · คะแนน 0.82 |
| หลัง `prepare --set ai.apply.enabled=true` | **6 ชิ้น · 0.7 นาที (≈ 44 วิ)** — ตรงเป้า 40–45 วิ ที่สั่ง |
| ชิ้นที่ได้ | 18.0 · 0.78 · 12.0 · 0.72 · 10.76 · 1.96 วิ |
| `render` + `assemble` ต่อ | **10.4 วิ** (ใช้ cache 1 ชิ้น ใหม่ 5) + 2.1 วิ → ไฟล์ **44.2 วิ · −14.0 LUFS** |

ใช้ได้จริง — นี่คือทางเดียวในเอนจินวันนี้ที่ย่อคลิปเดียวลงถึงเป้าได้ **แต่เจอเศษ 2 ชิ้น
(0.78 · 0.72 วิ)** จากขอบช่วงที่ AI ตอบเป็นวินาทีเต็ม (53.0 · 87.0) ไปเฉียดกับรอยตัดชน
(53.78 · 87.72): `intersect()` มี `floor=1.0` แต่ทำ**ก่อน** `cut_silence()` เศษจึงหลุดมา
([prepare.py:356](../vcut_engine/prepare.py#L356)) — แก้ได้ด้วยการย้ายเกณฑ์สั้นสุดไปหลังตัดชน
หรือดูดขอบ `keep` เข้าหารอยเงียบที่ใกล้ที่สุด (งานเล็ก แต่ต้องทำ ไม่งั้นได้ช็อตกระตุกครึ่งวินาที)

ข้อจำกัด: ใช้เวลาเป็นนาทีและกินโควตา · ตอบไม่ตรงบ้าง (ตัว `validate()` กันค่าเกินขอบให้แล้ว) ·
เห็นแต่ข้อความ — ถ้า transcript ไทยผิด (ตัวอย่างจริง: "เพชบูม" · "การประจนภัย") AI ก็เข้าใจผิดตาม

**ตำแหน่งที่เหมาะ:** เป็น 1–2 ใน 5 แบบ ("ไฮไลต์ AI") ไม่ใช่ทุกแบบ — แบบกฎล้วนต้องมีเสมอ
เพราะเร็ว ฟรี และให้ผลเดิมทุกครั้ง

## 9 · ข้อสรุปที่ต้องพูดให้ตรง

1. **เอนจินตัดคลิปเดียวได้ แต่ยังไม่รู้จัก "ย่อ"** — มันรู้จัก "เลือกชิ้น" จากกองใหญ่ พอกองมี
   ชิ้นเดียว ตรรกะเลือกก็ไม่มีอะไรให้เลือก G1 จึงเป็นงานแรกและสำคัญที่สุด ไม่ใช่หน้าเว็บ
2. **"2–5 แบบ" ถูกมาก** ถ้าต่างกันที่การเลือก/เรียง (4 วิ/แบบ) และ**แพงเท่าตัดใหม่**ถ้าต่างกัน
   ที่หน้าตา (ขั้น 4/5 ไม่มี cache) — ออกแบบให้แบบส่วนใหญ่ต่างที่การตัด และมีอย่างมาก 1–2 แบบ
   ที่ใส่หน้าตา
3. **คลิปตัวอย่าง `excemple-video-cut.mov` คือของที่ตัดเสร็จแล้ว** (−6.8 LUFS · ไม่มีเงียบ ·
   มีเพลง) ไม่ใช่ฟุตเทจดิบ — ใช้สอบเทียบเกณฑ์เงียบได้ดี แต่ผลตัดจะไม่สะท้อนงานจริง ควรหา
   คลิปดิบที่ถ่ายมือถือมาทดสอบขั้น 2–3 ก่อนสรุปค่า preset
4. transcript ภาษาไทยจาก whisper มีคำผิดพอสมควร — ซับอัตโนมัติต้องมีจุดให้คนแก้ก่อนเผา
   (ขั้น 4 มี `auto.edits` รองรับแล้ว) และอย่าใช้ข้อความนั้นเป็นการ์ด HOOK โดยไม่ให้ดูก่อน

### 10.1 หลักที่ใช้ตัดสินใจ

1. **โหมดง่ายคือ "หน้ากาก" ของโหมดเต็ม ไม่ใช่แอปที่สอง** — ทุกปุ่มยิง `/api/job` ·
   `/api/setup` · `/api/estimate` · `/upload/clip` ตัวเดิม และผลลัพธ์ของทุกแบบเป็น
   `edl.json` + `fx.json` ที่กด "เปิดในโหมดเต็ม" แล้วแก้ต่อได้ทันที
2. **คนตัดสินใจแค่ 3 อย่าง**: ไฟล์ไหน · สไตล์ไหน · อยากได้อะไรติดมาบ้าง — ที่เหลือ
   (135 ค่า) ถูก preset ตัดสินให้ และซ่อนอยู่หลัง "ตั้งค่าขั้นสูง" ในหน้าสุดท้ายเท่านั้น
3. **ของแพงต้องเห็นราคาก่อนกด** — AI (3 นาที · $0.5) กับชั้นหน้าตา (เข้ารหัสใหม่ทั้งเรื่อง)
   เป็นสวิตช์ที่ปิดเป็นค่าตั้งต้นและมีเวลา/ราคาเขียนข้าง ๆ ตัวเลขมาจาก `settings.estimate()`
4. **เลือกจากของจริง ไม่ใช่จากคำอธิบาย** — หน้าสุดท้ายต้องเล่นได้ทุกแบบ (`/out` ของแต่ละแบบ)

| AI ดูหนัง | หน้า ④ แผงขวา — ข้อเสนอ `cut/trim/text` ต่อแบบ กดรับแล้ว `assemble` ใหม่ 4 วิ |
| ไปป์ไลน์ 5 ขั้น | หน้า ③ ทั้งหน้า — 5 ขั้นเดิม แต่ขั้น ③ วนซ้ำตามจำนวนแบบ |

### 10.4 สิ่งที่หน้าเว็บทำไม่ได้จนกว่าเอนจินจะปิด G1–G5

mockup วาด "ภาพที่ควรเป็น" — แต่ปุ่ม "ตัดให้เลย" จะได้ผลตามภาพก็ต่อเมื่อ:
G1 (ย่อคลิปเดี่ยว) · G2 (เงียบ auto) · G3 (คำสั่ง `quick` + `variants/`) · G4 (preset 4 สไตล์) ·
G5 (`autofx`) เสร็จก่อน — ลำดับเดียวกับข้อ 8  ระหว่างนั้นหน้า ④ ทำได้แค่ 1 แบบ (ตัดชิดทั้งคลิป)
กับแบบ AI ไฮไลต์ ซึ่งคือสองแบบที่ทดสอบผ่านแล้วในข้อ 2 และ 5

## 12 · ยุบเหลือ 3 ขั้น — ① ใส่วิดีโอ → ② เลือกสไตล์ → ③ ส่งออก (ฟังก์ชันเอนจินครบ)

ตัดสินใจแล้ว (2 ก.ย. 2569): **รันการตัดในหน้า ② · เลือกแบบในหน้า ③ · ชั้นแต่งหนังตั้งค่าตั้งต้น
ในหน้า ② แล้วแก้รายแบบในหน้า ③ · ฟังก์ชันลึกอยู่ในลิ้นชัก "ขั้นสูง" ของหน้า ② ครบทุกอย่าง
+ ปุ่ม "โหมดเต็ม" สำหรับไทม์ไลน์**

### 12.1 ทุกฟังก์ชันของเอนจินไปอยู่ไหน — ตารางตรวจความครบ

| ฟังก์ชัน (คำสั่ง / โมดูล) | หน้า | รูปแบบที่โผล่ |
|---|---|---|
| `scan` · `thumbs` | ① | อัตโนมัติหลังวางไฟล์ · แถวสถานะ (ยาว · แนว · fps · ความดัง) |
| `listen` (whisper) | ① → วิ่งต่อเบื้องหลัง | เริ่มทันทีที่วางไฟล์ · ป้าย "ถอดเสียง 39 วิ" มุมขวาของหน้า ② — คนเลือกสไตล์ระหว่างรอ |
| preset · `RECIPES` | ② | การ์ดสไตล์ 4 ใบ |
| `[talk]` `[jumpcut]` `[broll]` `[compose]` `[order]` `[audio]` `[video]` `[encode]` … 135 ค่า | ② ขั้นสูง › **ตั้งค่า** | ฟอร์มเดียวกับ `SetupPanel` (สร้างจาก `settings.FIELDS`) — แสดง tier "ราคาของการแก้" |
| `compose` 7 โหมด (all · pattern · budget · numbers · timerange · manual · ai) + `[order]` 6 แบบ | ② ขั้นสูง › **วิธีเลือกชิ้น / ลำดับ** | เรดิโอ + ช่องของโหมดนั้น · manual = เปิดโหมดเต็ม |
| `ai` 4 งาน (story_arc · describe · shot_scoring · trim_suggest) + provider/model | ② สวิตช์ "AI ไฮไลต์" (= trim_suggest+shot_scoring) · ขั้นสูง › **AI** เลือกงานรายตัว/โมเดล/ผู้ให้บริการ | |
| `silence` · `prepare` · `compose` · `render` · `assemble` | ② ปุ่ม "ตัดให้เลย" → แถบความคืบหน้าในหน้าเดิม | ขั้น ③ วนตามจำนวนแบบ · เสร็จแล้วพาไป ③ |
| `caption` (ซับ auto · edits · drop · style) | ② ชั้น "ซับ" ค่าตั้งต้น · ③ แก้รายแบบ (รายบรรทัด) | |
| `fx` — text anim · shapes · overlays · music/sfx · clips fx · journey · beat | ② ชั้น "ข้อความ / เพลง / สติกเกอร์ / เอฟเฟกต์" ค่าตั้งต้น · ③ แก้รายแบบ (แผงเดียวกับ mockup ⑤) · แผนที่เส้นทาง/รูปทรง/แบ่งจอ = ขั้นสูง › **เพิ่มเติม** (เปิดโหมดเต็ม) | |
| `review` 6 งาน | ③ แผง "AI ดูหนัง" รับ/ข้ามทีละข้อ | |
| `/upload/clip` · `/api/asset` · `/api/music` (yt-dlp) · `/api/beats` | ① · ③ ในแผงสติกเกอร์/เพลง | |
| `reset` (--scope · --list · --restore) · `gc` · `info` · `presets` | ② ขั้นสูง › **รีเซ็ต/ประวัติ** · **cache/สถานะ** | |
| `view` (ไทม์ไลน์ · ลากช็อต · การ์ดลอย · มิกเซอร์) | ปุ่ม "โหมดเต็ม" ทุกหน้า | โปรเจกต์เดียวกัน เปิดต่อได้ทันที |

ไม่มีฟังก์ชันไหนถูกตัด — ที่ย้ายไป "โหมดเต็ม" มีแค่ *การลากบนไทม์ไลน์* กับ *แผนที่เส้นทาง/รูปทรง/แบ่งจอ*
ซึ่งต้องการจอตัวอย่างเต็มอยู่แล้ว

### 12.2 ทำไมถอดเสียงตั้งแต่หน้า ①

`listen` คือครึ่งหนึ่งของเวลาทั้งหมด (39 จาก 80 วิ) และ**ทุกแบบใช้ transcript ร่วมกัน** — เริ่มตอนวางไฟล์
แล้วคนใช้เวลาเลือกสไตล์ ~30–60 วิ พอกด "ตัดให้เลย" transcript เสร็จพอดี เหลือแค่ silence + render ≈ 40 วิ
(ราคา: ถ้าคนเปลี่ยนใจไม่ตัด เสียเวลา CPU 39 วิ ซึ่งยอมรับได้)

### 12.3 หน้า ② คือ "โต๊ะทำงาน" — สามชั้นซ้อนกันในหน้าเดียว

```
ชั้นบน   สไตล์ 4 ใบ · ความยาว · จำนวนแบบ · AI                     ← คนทั่วไปแตะแค่นี้
ชั้นกลาง ชั้นแต่งหนัง 5 แถว (ซับ · ข้อความ · เพลง · สติกเกอร์ · เอฟเฟกต์)  ← เปิดดูได้ มีค่าตั้งต้นจากสไตล์
ลิ้นชัก  ขั้นสูง: ตั้งค่า 135 · วิธีเลือกชิ้น · ลำดับ · AI · รีเซ็ต/ประวัติ · cache/สถานะ · เพิ่มเติม
```

กด "ตัดให้เลย" แล้ว **ชั้นบน/กลางล็อก** (จาง) · คอลัมน์ขวากลายเป็นความคืบหน้า 5 ขั้น + แบบที่ทยอยเสร็จ
· เสร็จแล้วพาไป ③ เอง (กดหยุดได้ · กด "ดู" แบบที่เสร็จก่อนได้)

### 12.4 หน้า ③ ส่งออก = เลือกแบบ + แต่งรายแบบ + AI + ไฟล์

แกลเลอรี (ติ๊กเลือกส่งออกได้หลายแบบ) · ตัวเล่น + แถบเวลาย่อ · แผงขวา 3 ส่วน: **แต่งแบบนี้**
(5 แถวเดิม แต่เป็นค่าของแบบนั้น · "แก้" เปิดแผงเดียวกับ mockup ⑤ เป็นลิ้นชัก) · **AI ดูหนัง** ·
**ส่งออก** (ไฟล์ ③/④/⑤ · ปลายทาง · Finder) — แก้แล้วขึ้นป้าย "ทำขั้น ⑤ ใหม่ ~45 วิ" ก่อนส่งออก
