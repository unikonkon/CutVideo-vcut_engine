# vcut_engine — เอนจินทำงานอย่างไร

เอกสารนี้อธิบาย **กลไกภายใน** ของ vcut_engine ว่าโค้ดที่ไม่ได้ลง library ตัวไหนเลย
"อ่าน" วิดีโอรู้เรื่องได้อย่างไร แยกเสียงคนกับเสียงบรรยากาศได้อย่างไร และพื้นฐาน
การออกแบบระบบตัดต่ออัตโนมัติแบบนี้คืออะไร

> คู่มือใช้งานคำสั่ง · config · preset ทั้งหมด อยู่ที่ [vcut README.md](vcut%20README.md)

**สรุปหนึ่งบรรทัด:** vcut_engine ไม่ใช่ video processing library — มันคือ *ระบบตัดสินใจ*
ที่ output เป็น JSON แล้วให้ ffmpeg ลงมือทำแทน

## 1. ไม่มี library ภายนอกเลย — จริงไหม

**จริง** โปรเจกต์นี้ไม่มี `requirements.txt`, `pyproject.toml`, `setup.py`
และ import ทั้งหมดใน [vcut_engine/](vcut_engine/) เป็น Python standard library ล้วน:

```
subprocess · json · re · pathlib · hashlib · shutil · time · tomllib
argparse · concurrent.futures · http.server · mimetypes · webbrowser · calendar
```

ไม่มี `numpy` · `opencv` · `moviepy` · `ffmpeg-python` · `torch` · `whisper` (Python) ·
`anthropic` SDK — ไม่มีเลยแม้แต่ตัวเดียว

### แต่มันเรียกโปรแกรมภายนอก 4 ตัวผ่าน `subprocess`

| เครื่องมือ | หน้าที่ | จุดที่เรียก |
|---|---|---|
| `ffprobe` | อ่าน metadata วิดีโอเป็น JSON | [util.py:83](vcut_engine/util.py#L83) |
| `ffmpeg` | วัดค่า · ตัด · แปลง · ต่อ | เกือบทุกโมดูล |
| `whisper-cli` (whisper.cpp) | ถอดเสียงเป็นข้อความพร้อมเวลา | [listen.py:62](vcut_engine/listen.py#L62) |
| `claude` (Claude Code CLI) | ให้ความเห็นเชิงเนื้อหา (ปิดได้) | [ai.py:318](vcut_engine/ai.py#L318) |

[cli.py:416](vcut_engine/cli.py#L416) เช็ค `ffmpeg`/`ffprobe` ก่อนเริ่มงาน ไม่มีก็หยุดทันที
ส่วน `whisper-cli` เช็คเฉพาะตอนที่มีคลิปต้องถอดจริง ๆ ([listen.py:110](vcut_engine/listen.py#L110))

**ขั้น 4 กับขั้น 5 ไม่ได้เพิ่มเครื่องมือใหม่สักตัว** — ตัวหนังสือ · แอนิเมชัน · ลูกศร ·
ภาพซ้อน · สโลว์โม · โทนสี · เพลงคลอ ทั้งหมดเป็นฟิลเตอร์ที่ ffmpeg มีอยู่แล้ว
เงื่อนไขเดียวที่เพิ่มมาคือ **ffmpeg ตัวที่คอมไพล์ฟิลเตอร์ `ass` มาด้วย** ซึ่ง homebrew
ย้ายไปไว้ที่สูตร `ffmpeg-full` ([caption.py:115](vcut_engine/caption.py#L115) หาให้เอง
แล้วบอกวิธีติดตั้งถ้าไม่เจอ — ขั้น 1–3 ยังใช้ ffmpeg ตัวไหนก็ได้เหมือนเดิม)

นี่คือ **Unix philosophy** เต็มรูปแบบ — Python เป็น "สมอง" ที่ตัดสินใจว่าจะสั่งอะไร
ส่วน "กล้ามเนื้อ" คือ CLI ที่ compile มาแล้วเป็น C/C++ ซึ่งเร็วกว่า Python หลายสิบเท่า
และไม่ต้องแบก dependency tree ที่พังทุกครั้งที่อัปเดต Python

โค้ด Python ทุกบรรทัดในโปรเจกต์นี้ทำอยู่แค่ 3 อย่าง:

1. **ประกอบสตริง** คำสั่ง ffmpeg
2. **regex แกะตัวเลข** ที่ ffmpeg พ่นออก stderr
3. **เก็บผลเป็น JSON** พร้อมระบบ cache

## 2. โค้ดอ่านค่าวิดีโอ "รู้เรื่อง" ได้อย่างไร

หัวใจคือเทคนิคเดียว:

> **ใช้ ffmpeg เป็นเครื่องมือวัด แล้วดักค่าจาก stderr ด้วย regex**

ffmpeg มี filter หลายตัวที่พิมพ์ตัวเลขออก log ได้ โค้ดจึงรัน ffmpeg แบบทิ้ง output
(`-f null -`) แล้วเอา **stderr มาเป็นสายข้อมูล** ไม่มีการ decode เฟรมเข้ามาใน
Python memory แม้แต่เฟรมเดียว

### 2.1 คุณสมบัติพื้นฐาน → `ffprobe` JSON

[util.py:94](vcut_engine/util.py#L94) `probe_video()` ดึงออกมาเป็น dict เดียว:

| ค่า | ใช้ทำอะไรต่อ |
|---|---|
| `duration` | คำนวณช่วงตัดทุกอย่าง |
| `w`/`h` + `rotation` side_data | หาทิศจริง — ffmpeg autorotate ไปแล้วชั้นหนึ่ง ถ้าหมุน 90/270 ขนาดที่ decoder พ่นออกมาจะสลับ จึงเก็บทั้ง `w/h` (ดิบ) และ `dw/dh` (หลังหมุน) |
| `fps` vs `avg_fps` | ต่างกันเกิน 0.5 = **VFR** (frame rate ไม่คงที่) ต้องบังคับ CFR ตอน render ไม่งั้นเสียงกับภาพจะเลื่อน |
| `pix_fmt`, `color_range` | จับคลิป full range ที่ต้องแปลงเป็น tv range ไม่งั้นสีจะซีด/จม |
| `acodec`, `achannels`, `arate` | คลิปไม่มีเสียง (0 ch) ต้องยัด silent track ให้ตอน render ไม่งั้น concat พัง |
| `creation_time` | **เวลาถ่ายจริง** — `mtime` ของไฟล์เชื่อไม่ได้ พอ copy ฟุตเทจมาก็เปลี่ยนหมด |

### 2.2 ความสั่น / การเคลื่อนไหว (motion) — [util.py:171](vcut_engine/util.py#L171)

```
fps=5,scale=64:36,format=gray,tblend=all_mode=difference,
signalstats,metadata=print:key=lavfi.signalstats.YAVG
```

แปลไทยทีละขั้น:

1. `fps=5` — สุ่มเฟรม 5 ต่อวินาที (ไม่ต้องดูทุกเฟรม)
2. `scale=64:36` — ย่อเหลือ 64×36 พิกเซล เร็วขึ้นหลายร้อยเท่า และรายละเอียดที่หายไปไม่มีผลกับสิ่งที่จะวัด
3. `format=gray` — ทิ้งสี เหลือความสว่างอย่างเดียว
4. `tblend=all_mode=difference` — **เอาเฟรมนี้ลบเฟรมก่อนหน้า** ได้ "ภาพผลต่าง"
5. `signalstats` + `metadata=print` — วัดความสว่างเฉลี่ย (`YAVG`) ของภาพผลต่างนั้น แล้วพิมพ์ลง log

ตีความ:

```
ภาพผลต่างสว่าง   →  สองเฟรมต่างกันมาก  →  กล้องสั่น / แพนเร็ว / ของเคลื่อนที่เยอะ
ภาพผลต่างดำสนิท  →  สองเฟรมเหมือนกัน   →  ภาพนิ่ง (ขาตั้ง / ล็อกช็อต)
```

Python ทำแค่:

```python
m = [float(x) for x in _RE_YAVG.findall(stderr)]
return round(sum(m) / len(m), 2)
```

**นี่คือ optical flow แบบคนจน ที่ไม่ต้องใช้ OpenCV เลย** วัดแค่ 20 วินาทีแรกของคลิป
(`scan.motion_window`) ก็พอตัดสินว่าช็อตนี้นิ่งหรือสั่น

ค่านี้ถูกใช้สองที่: คัดคลิปที่สั่นเกินทิ้ง (`broll.drop_above_motion`) และ
**กำหนดความยาว B-roll** — [prepare.py:109](vcut_engine/prepare.py#L109) `broll_duration()`
ช็อตนิ่งให้อยู่นาน 4 วิ ช็อตที่เคลื่อนไหวเยอะให้แค่ 1.5 วิ เพราะดูนานแล้วเวียนหัว

### 2.3 ความสว่าง (bright)

```
fps=2,scale=64:36,signalstats,metadata=print:key=lavfi.signalstats.YAVG
```

เหมือนข้อบนแต่ไม่มี `tblend` — ได้ค่าความสว่างเฉลี่ยตรง ๆ ใช้คัดคลิปที่มืดจนใช้ไม่ได้
(`broll.drop_below_bright`)

### 2.4 ความดัง — LUFS / true peak — [util.py:153](vcut_engine/util.py#L153)

```
-vn -af ebur128=peak=true:framelog=quiet
```

`ebur128` คือมาตรฐาน **EBU R128** ที่วงการ broadcast ใช้จริง — วัด "ความดังที่หูคนได้ยิน"
ไม่ใช่แค่ค่าพีคของคลื่น แล้ว regex ดึงสองค่า:

```python
_RE_I  = re.compile(r"I:\s+(-?[\d.]+)\s+LUFS")     # integrated loudness
_RE_TP = re.compile(r"Peak:\s+(-?[\d.]+)\s+dBFS")  # true peak
```

`-vn` ทิ้งภาพทั้งหมด จึงเร็วมาก และวัดเฉพาะช่วง `-ss`/`-t` ที่ระบุได้ด้วย
(ใช้ตอนวัดความดังของ *ชิ้นที่จะตัด* ไม่ใช่ทั้งคลิป — [render.py:120](vcut_engine/render.py#L120))

### 2.5 ช่วงเงียบ — [silence.py:33](vcut_engine/silence.py#L33)

```
-map 0:a:0 -af silencedetect=noise=-32dB:d=0.45
```

ffmpeg พ่นบรรทัดแบบนี้ออก stderr:

```
[silencedetect @ ...] silence_start: 12.345
[silencedetect @ ...] silence_end: 13.012 | silence_duration: 0.667
```

โค้ดไล่อ่านทีละบรรทัด จับคู่ start/end เป็นช่วง `[a, b]` และมีเคสที่ต้องดูแลเอง:
**เงียบยาวไปจนจบคลิป** — จะไม่มี `silence_end` ต้องปิดช่วงด้วยความยาวคลิปเอง
([silence.py:49](vcut_engine/silence.py#L49))

## 3. แยก "เสียงคน" กับ "เสียงบรรยากาศ" ได้อย่างไร

**ต้องพูดให้ตรง: มันไม่ได้แยกเสียงคนออกจากเสียงบรรยากาศ (source separation)**
ไม่มี demucs, ไม่มี VAD model, ไม่มี speaker diarization

มันใช้ **สามชั้นที่คนละหลักการ** ซ้อนกัน แล้วได้ผลที่ใกล้เคียงกับการแยกจริง

### ชั้นที่ 1 — ใช้ ASR เป็นตัวตรวจจับเสียงพูด

[listen.py:48](vcut_engine/listen.py#L48) แปลงเสียงเป็นรูปแบบที่ whisper ต้องการ:

```
ffmpeg -i คลิป -vn -ar 16000 -ac 1 -c:a pcm_s16le out.wav
```

(16 kHz · mono · PCM 16-bit — ถ้าไม่ตรงนี้ whisper.cpp จะปฏิเสธ)

แล้วโยนให้ `whisper-cli -oj` ได้ JSON กลับมา parse เป็น `[[start, end, text], ...]`

**ตรรกะแยกประเภทอยู่ที่** [prepare.py:196](vcut_engine/prepare.py#L196):

```python
speech = round(sum(b - a for a, b, _ in segs), 2)
kind = "TALK" if (segs and speech >= thr) else "BROLL"
```

- whisper ถอดออกมาเป็นคำ และเวลาพูดรวมเกิน `classify.min_speech_total` (ตั้งต้น 1.0 วิ) → **TALK**
- คลิปวิว เสียงลม เสียงคลื่น เสียงรถ — whisper ถอดไม่ได้หรือได้ไม่ถึงเกณฑ์ → **BROLL**

จุดที่ฉลาดคือ **ใช้ ASR เป็น speech detector ที่เข้าใจความหมาย** ไม่ใช่แค่เครื่องวัด
พลังงานเสียง — เสียงลมดังลั่นก็ยังเป็น BROLL เพราะไม่มีคำออกมา ส่วนคนกระซิบเบา ๆ
ท่ามกลางความเงียบก็ยังเป็น TALK

มีตัวกรอง **hallucination** ด้วย ([listen.py:15](vcut_engine/listen.py#L15)) — whisper ชอบเดา
ว่า "ขอบคุณครับ" หรือ "ซับไทยโดย..." เวลาเจอช่วงเงียบ จึงมี regex ใน
`[listen.filter] hallucination` คอยตัดทิ้งก่อนเข้าสู่ระบบ

### ชั้นที่ 2 — ใช้ amplitude threshold หาช่องว่างในประโยค

Comment ที่ [silence.py:3](vcut_engine/silence.py#L3) อธิบายเหตุผลไว้ตรง ๆ:

> whisper คืนช่วงมาหยาบมาก ฟุตเทจชุดนี้ 109 จาก 116 คลิปพูดได้ช่วงเดียวยาว ๆ
> ทั้งคลิป — ช่วงที่คนหยุดคิด หายใจ หรือเดินเงียบ ๆ อยู่ในนั้นหมด
> ตัดตาม transcript อย่างเดียวจึงตัดอะไรออกไม่ได้เลย

เลยต้องวัดคลื่นเสียงตรง ๆ ด้วย `silencedetect` แล้ว [prepare.py:56](vcut_engine/prepare.py#L56)
`cut_silence()` เอาช่วงเงียบไป **คว้านออกจากช่วงพูด** → ได้ jump cut ที่ประโยคชนประโยค

รายละเอียดที่ทำให้ไม่พัง:

| กลไก | ป้องกันอะไร |
|---|---|
| `pad` หดช่วงเงียบเข้าข้างละ 0.1 วิ | ตัดโดนพยัญชนะต้น/ท้ายคำ |
| `min_piece` ทิ้งชิ้นที่สั้นเกิน | เศษ 0.2 วิ ที่ดูเป็นความผิดพลาด ไม่ใช่การตัดสินใจ |
| ถ้าคว้านแล้วไม่เหลืออะไรเลย → คืนช่วงเดิม | ตั้งค่าพลาดแล้วคลิปหายทั้งอัน |
| ฟิลด์ `jump` ล็อกชิ้นที่มาจากประโยคเดียวกัน | ขั้น 3 เอาช่วงวิวไปแทรกกลางประโยค — นั่นไม่ใช่ cut ชน แต่คือประโยคขาด |

ขั้นนี้ทำเฉพาะคลิปที่ whisper บอกว่ามีคนพูด และมี audio track จริง
([silence.py:66](vcut_engine/silence.py#L66)) — คลิปวิวถูกตัดด้วยกฎความยาวอยู่แล้ว
ไม่ได้ตัดตามเสียง

### ชั้นที่ 3 — จัดการเสียงบรรยากาศด้วย "ระดับเสียง" ไม่ใช่ด้วยการแยก

[prepare.py:162](vcut_engine/prepare.py#L162):

```python
lufs_t = ctx.get("audio.target_lufs_talk",  -19.0)   # คลิปพูด → ดัง ฟังชัด
lufs_b = ctx.get("audio.target_lufs_broll", -26.0)   # คลิปวิว → เบาลง 7 dB
```

"เสียงบรรยากาศ" ถูกจัดการโดย **ตั้งเป้าความดังคนละค่า** ตอนตัดต่อ ไม่ใช่โดยการ
แยกสัญญาณ แล้ว [render.py:57](vcut_engine/render.py#L57) `compute_gain()` คำนวณว่าต้อง
เร่ง/ลดกี่ dB:

```python
g_loud = target - I                      # ต้องเร่งเท่าไรถึงได้ความดังที่ต้องการ
g_peak = (ceiling + allow) - TP          # เร่งได้มากสุดเท่าไรก่อนพีคทะลุ
gain = min(g_loud, g_peak)               # เอาค่าที่น้อยกว่า
```

> ถ้าดูความดังอย่างเดียว คลิปที่เบามากจะถูกเร่งจนพีคทะลุ แล้วโยนภาระให้ limiter
> บีบจนเสียงแบน — สูตรนี้กันไม่ให้ไปถึงจุดนั้นตั้งแต่แรก

จบด้วย `alimiter` เป็นตาข่ายรองสุดท้าย และ `afade` เข้า/ออก 0.02 วิ กันเสียง "แป๊ะ"
ตอนต่อชิ้น ([render.py:72](vcut_engine/render.py#L72))

### ข้อจำกัดที่ต้องรู้

### 4.1 EDL — แยก "การตัดสินใจ" ออกจาก "การลงมือ"

แนวคิดเก่าแก่ของวงการตัดต่อ (Edit Decision List) ทุกขั้นตอนคือ **JSON หนึ่งไฟล์**
ที่อ่านออกด้วยตาเปล่า และ debug ได้ด้วย `cat`

```
manifest.json   คุณสมบัติทุกคลิป
transcript.json { คลิป: [[start, end, text], ...] }
silence.json    ช่วงเงียบ
ai.json         ความเห็นของ AI (ถ้าเปิดใช้)
pool.json       คลังชิ้น — ทุกชิ้นที่ตัดได้
edl.json        ★ หยิบชิ้นไหน เรียงยังไง  ← สัญญากลางของทั้งระบบ
render.json     ชิ้นไหนอยู่ไฟล์ไหน gain เท่าไร
captions.json   ขั้น 4 · เขียนว่าอะไร ฟอนต์อะไร อยู่ตรงไหน
fx.json         ขั้น 5 · แต่งอะไรไว้บ้าง (คลิป · ข้อความ · รูปทรง · ภาพซ้อน · เพลง)
fx-render.json  ขั้น 5 · หลังใส่เอฟเฟกต์แล้วหนังมีชิ้นอะไร ยาวเท่าไร
```

`fx-render.json` เป็นไฟล์เดียวในกองนี้ที่ **คำนวณใหม่ทุกครั้ง ไม่เคยอ่านของเก่า** —
มันเป็น *ผลลัพธ์* ของ `render.json` + `fx.json` ซึ่งแก้ได้ตลอด ไม่ใช่สถานะที่ต้องจำ
เก็บไว้อ่านเมื่อไรก็มีวันที่มันตกยุคโดยไม่มีใครรู้ ([fx.py:583](vcut_engine/fx.py#L583))

`edl.json` แก้ด้วยมือได้ แล้ว `render`/`assemble` ทำตามทันที — หน้าเว็บ
([serve.py](vcut_engine/serve.py)) ก็แค่ UI ที่เขียนไฟล์นี้อีกที ไม่มีสถานะซ่อนอยู่ที่ไหน

สังเกตการออกแบบ `pool.json` ที่ [prepare.py:12](vcut_engine/prepare.py#L12):

> pool.json เก็บ **ทุกชิ้น** รวมทั้งชิ้นที่ตัวกรองคัดออก (ติดธง `ok=false` พร้อม
> เหตุผล) เพื่อให้หน้าเว็บหยิบกลับมาใส่เองได้ถ้าไม่เห็นด้วยกับตัวกรอง

**ไม่ทิ้งข้อมูลหาย** — ของที่ถูกคัดออกยังอยู่ พร้อมคำอธิบายว่าคัดเพราะอะไร
("ภาพสั่น motion 18.2 ≥ 15") เดิมชิ้นที่ไม่ถูกเลือกหายไปเลย ไม่เหลือร่องรอย

### 4.2 Content-hash cache — งานหนักทำครั้งเดียว

[render.py:145](vcut_engine/render.py#L145) `seg_key()` คือกุญแจของทั้งระบบ:

```python
return key_of({
    "src": seg["src"], "sig": [ขนาดไฟล์, mtime],
    "start": ..., "dur": ...,
    "vf": build_vfilter(seg, ctx),    # ฟิลเตอร์ภาพทั้งสตริง
    "af": build_afilter(seg, gain, ctx),  # ฟิลเตอร์เสียงทั้งสตริง
    "enc": encode_args(ctx), "fps": ..., "silent": ...,
})
```

sha1 ของ **ทุกอย่างที่มีผลต่อภาพ/เสียงของชิ้นนั้น** → เอาไปเป็นชื่อไฟล์
`segments/<hash>.mp4`

สิ่งที่ **ไม่อยู่** ใน hash สำคัญพอกัน — ไม่มีคำว่า "ลำดับ" อยู่ในนั้น:

```
สลับลำดับใน EDL / ลบช็อตออก  →  render ไม่ทำงานเลยสักชิ้น
เปลี่ยนความยาว B-roll        →  render ใหม่เฉพาะชิ้นวิว
เปลี่ยน preset ทั้งชุด        →  render ใหม่เฉพาะชิ้นที่พารามิเตอร์เปลี่ยนจริง
```

หลักการเดียวกันใช้ทุกขั้น แต่ปรับตามลักษณะงาน:

| ขั้น | ตรวจ cache ด้วย |
|---|---|
| [scan.py:99](vcut_engine/scan.py#L99) | ขนาดไฟล์ + mtime ของต้นฉบับ |
| [silence.py:74](vcut_engine/silence.py#L74) | เฉพาะ `noise_db` + `min_silence` — ค่าอื่นใน `[jumpcut]` เปลี่ยนไม่ต้องฟังใหม่ |
| [listen.py:85](vcut_engine/listen.py#L85) | มีชื่อคลิปใน transcript แล้วหรือยัง + `import_dir` ดึงผลรอบก่อนมาใช้ได้ |
| [clips.py:286](vcut_engine/clips.py#L286) | hash ของฟิลเตอร์ + ช่วงเวลา (ตัวอย่าง 3 วิในหน้าเว็บ) |
| [fx.py:481](vcut_engine/fx.py#L481) | ฟิลเตอร์เอฟเฟกต์ + จำนวนเฟรม + **ลายเซ็นของ segment ขั้น 3 ที่เป็นต้นทาง** |

แถวสุดท้ายมีรายละเอียดที่ต้องคิดเพิ่ม: ขั้น 5 แต่งต่อจากไฟล์ที่ *ขั้น 3 สร้างขึ้น*
ซึ่งถูกสร้างใหม่ได้ตลอดถ้ามีคนแก้ค่าฝั่งนั้น กุญแจจึงต้องรวม (ขนาด + mtime) ของไฟล์
ต้นทางเข้าไปด้วย ไม่งั้นแก้ค่าที่ขั้น 3 แล้วขั้น 5 จะยังคืน cache ของภาพเก่าให้

มีอีกจุดที่แสดงวิธีคิดชัดมาก — [clips.py:13](vcut_engine/clips.py#L13):

> **หมุนคลิปแล้วไม่ต้อง scan ใหม่** — `rot_override` มีผลแค่กับ orient/dw/dh
> ส่วน motion · ความสว่าง · ความดัง วัดจากไฟล์ดิบก่อนหมุนทั้งหมด
> แก้ manifest ตรงจุดจึงถูกต้องเท่ากับ scan ใหม่ทั้งกอง แต่ใช้เวลาไม่ถึงวินาที
> แทนที่จะเป็น 40 นาที

### 4.3 One-pass render + stream-copy concat

[render.py:162](vcut_engine/render.py#L162) `render_one()` ทำ **ทุกอย่างในคำสั่ง ffmpeg เดียว**:

```
หมุนภาพ · แนวตั้ง→พื้นหลังเบลอ · full range→tv · scale+pad · CFR
mono→stereo (ยัด anullsrc ถ้าคลิปไม่มีเสียง) · gain · limiter · fade เข้า/ออก
```

เข้ารหัสรอบเดียวจบ — ไม่มี intermediate file ไม่มี generation loss

แล้ว [assemble.py](vcut_engine/assemble.py) ต่อด้วย `-f concat -c copy`:

> ต่อโดยไม่เข้ารหัสซ้ำ: เปลี่ยนลำดับ/ตัดชิ้นออกแล้วต่อใหม่ได้ในไม่กี่วินาที
> ภาพและเสียงคุณภาพเท่าเดิมเป๊ะ

ทำได้เพราะสองเงื่อนไขที่บังคับไว้ตั้งแต่ตอน render:

1. ทุกชิ้น encode ด้วยพารามิเตอร์เดียวกัน (codec · profile · fps · sample rate · channel)
2. [render.py:105](vcut_engine/render.py#L105) บังคับ keyframe ทุก 1 วินาที
   `-force_key_frames expr:gte(t,n_forced*1.0)`

กรณีเดียวที่ต้องเข้ารหัสเสียงใหม่คือเปิด `audio.master_lufs` เพื่อทำ loudnorm ทั้งเรื่อง
— ตอนนั้น **ภาพยัง copy ได้** เข้ารหัสใหม่แค่เสียง ([assemble.py:41](vcut_engine/assemble.py#L41))

จบด้วย `verify()` ที่ probe ไฟล์ผลลัพธ์กลับมาเทียบกับ EDL: ความยาวเพี้ยนไปกี่วินาที
ความดังรวมเท่าไร limiter ทำงานกี่ชิ้น — **ตรวจงานตัวเองทุกครั้ง** (ขั้น 4 กับขั้น 5
ใช้ตัวตรวจตัวเดียวกันนี้ แต่ขั้น 5 ส่งความยาว *หลัง* ใส่เอฟเฟกต์ไปเทียบ ไม่งั้น
พอมีสโลว์โมมันจะเตือนว่าความยาวเพี้ยนทุกครั้ง)

**ขั้น 4 กับขั้น 5 คือที่เดียวที่ยอมจ่ายค่าเข้ารหัสรอบที่สอง** — เขียนตัวหนังสือลง
ภาพแปลว่าต้องแตะพิกเซล จะ `-c copy` ต่อไปไม่ได้อีก ทั้งสองขั้นจึงยุบทุกชั้นที่ต้องทำ
(ข้อความ · ภาพซ้อน · ผสมเพลง · ปรับความดังรวม) ไว้ใน **คำสั่ง ffmpeg เดียว** แทนที่
จะแต่งทีละชั้นทับไฟล์ไปเรื่อย ๆ ซึ่งจะเสียคุณภาพสี่รอบและใช้เวลาสี่เท่า
([finish.py:7](vcut_engine/finish.py#L7))

### 4.4 Filter graph — ที่มาของ "แนวตั้งเป็นแนวนอน"

[render.py:19](vcut_engine/render.py#L19) `build_vfilter()` มี 3 โหมดสำหรับคลิปแนวตั้ง
โหมด `blur_pad` คือ filter_complex เต็มรูป:

```
[0:v]split=2[bg][fg];                            แยกภาพเป็นสองสาย
[bg]scale→crop→gblur→eq→scale 1920:1080[bgb];    สายหลัง: เบลอ หรี่ ลดสี
[fg]scale=-2:1080[fgs];                          สายหน้า: ภาพจริงเต็มความสูง
[bgb][fgs]overlay=(W-w)/2:0,setsar=1,format=yuv420p[v]
```

ไม่มี compositing engine ใน Python เลย — ทุกอย่างเป็นสตริงที่ส่งให้ ffmpeg
และ [clips.py:264](vcut_engine/clips.py#L264) `preview()` ใช้ `build_vfilter` **ตัวเดียวกัน**
ตัด 3 วินาทีกลางคลิปให้ดูในหน้าเว็บ:

> ที่เห็นในหน้าเว็บจึงเป็นสิ่งที่จะได้จริง ๆ ไม่ใช่ภาพจำลองที่ใกล้เคียง

รายละเอียดเล็ก ๆ ที่ต้องคิดเอง — [scan.py:29](vcut_engine/scan.py#L29) `swaps_wh()`
นับจำนวน `transpose` ไม่ใช่แค่ดูว่ามีไหม เพราะ `transpose=1,transpose=1` คือหมุน 180°
ซึ่งขนาดเท่าเดิม

### 4.5 AI เป็น "ที่ปรึกษา" ไม่ใช่ "คนลงมือ"

Docstring [ai.py:1](vcut_engine/ai.py#L1) วางกฎไว้ชัด:

> เอนจินยังคงคาดเดาได้ 100% เหมือนเดิม เพราะ AI เขียนได้แค่ไฟล์เดียวคือ
> `.vcut/ai.json` ซึ่งเป็น "ความเห็น" ล้วน ๆ

AI ตอบได้แค่ 4 อย่าง: แบ่งบทเล่าเรื่อง · อ่านความหมายรายคลิป · ให้คะแนนช็อต 0–1 ·
แนะนำช่วงที่ควรเก็บ จากนั้น [prepare.py:151](vcut_engine/prepare.py#L151) เอาไปใช้ด้วย
**กฎที่เขียนตายตัว** ใน `[ai.apply]` ซึ่งเปิด/ปิดได้ทีละอย่าง (`trim` · `drop` · `order`)

ผลที่ได้:

- รัน `vcut decide` ซ้ำกี่ครั้งก็ไม่เสียเงินเรียก AI ใหม่ (อ่านจาก `ai.json`)
- commit `ai.json` เข้า git ได้ → คนอื่นได้ผลเดียวกันโดยไม่ต้องมี API key
- ปิด `[ai] enabled = false` เมื่อไหร่ ก็กลับไปเป็นเอนจินกฎล้วนเป๊ะ ๆ

**แบ่งหน้าที่ระหว่าง AI กับกฎ** — [prepare.py:127](vcut_engine/prepare.py#L127):

> AI เลือก "ตรงไหนของคลิป" · กฎยังเป็นคนกำหนด "ยาวเท่าไร"
> แยกหน้าที่แบบนี้เพื่อให้จังหวะหนัง (pacing) ยังคุมได้จาก config เหมือนเดิม

**กันพลาด** — [prepare.py:243](vcut_engine/prepare.py#L243) ถ้าช่วงที่ AI แนะนำไม่ทับกับ
ช่วงที่พูดจริงเลย ให้ **เชื่อ VAD ไว้ก่อน** ดีกว่าทำคลิปหายทั้งอันโดยไม่ตั้งใจ
แล้วเตือนผู้ใช้ว่าเกิดขึ้นกี่คลิป

**AI เห็นอะไรบ้าง:**

| ส่ง | ไม่ส่ง |
|---|---|
| ตารางคลิปละบรรทัด (ชื่อ · ลำดับ · วินาที · ประเภท · พูดกี่วิ · motion · สว่าง · แนว) | ไฟล์วิดีโอ |

contact sheet คือกุญแจของการประหยัด ([thumbs.py:1](vcut_engine/thumbs.py#L1)):

> ส่งภาพ 273 ใบให้ AI ดูทีละใบสิ้นเปลืองมาก รวมเป็นตาราง 5×5 เหลือ 11 แผ่น

เรียก AI ผ่าน `claude -p --output-format json` ([ai.py:318](vcut_engine/ai.py#L318))
แล้วอ่านคำตอบจาก **ไฟล์ที่ AI เขียน** ก่อน ถ้าไม่มีค่อยแกะ JSON จาก stdout —
พร้อมเก็บ raw log ไว้ทุกครั้ง และรายงาน cost/turns/tokens กลับมา

### 4.6 Parallelism ที่ได้ผลจริง เพราะงานหนักอยู่นอก Python

`ThreadPoolExecutor` โผล่ใน [scan](vcut_engine/scan.py#L123) · [silence](vcut_engine/silence.py#L87) ·
[thumbs](vcut_engine/thumbs.py#L40) · [render](vcut_engine/render.py#L238)

ปกติ thread ใน Python ติด GIL แต่ที่นี่ได้ผลเต็ม ๆ เพราะทุก worker แค่ **นั่งรอ
subprocess** — GIL ถูกปล่อยระหว่างรอ I/O จึงขนานได้จริงโดยไม่ต้องใช้ `multiprocessing`

สังเกตค่าตั้งต้นที่ต่างกัน: `scan.workers = 6` แต่ `render.workers = 2` — เพราะ probe
กับ measure แทบไม่กิน CPU ส่วน encode กิน hardware encoder จริง เปิดเยอะไปกลับช้าลง

### 4.7 ชั้นบนเป็น "สาขาคู่ขนาน" ไม่ใช่ขั้นที่เขียนทับของเดิม

ขั้น 4 (ข้อความ) กับขั้น 5 (แต่งหนัง) ต่อยอดจากขั้น 3 โดย**ไม่แก้โค้ดของขั้น 3
แม้แต่บรรทัดเดียว** — ทั้งคู่อ่าน `render.json` + `segments/` แล้วเขียนไฟล์ของตัวเอง

```
                    ┌─ ขั้น 4  caption ──► final-text.mp4
edl.json ─► segments ┤
                    └─ ขั้น 5  finish ───► final-fx.mp4     (อ่าน captions.json ด้วย)
```

**ขั้น 5 อ่านของขั้น 4 แต่ไม่ได้ต่อจากมัน** — ตัวหนังสือที่ถูกเผาลงภาพไปแล้วทำให้
เคลื่อนไหวไม่ได้อีก ขั้น 5 จึงอ่าน *ข้อมูลข้อความ* (`captions.json`) ไม่ใช่ *ไฟล์วิดีโอ
ที่มีข้อความ* แล้วเขียน ASS ของตัวเองที่มีแท็กแอนิเมชันครบ

แบ่งความเป็นเจ้าของกันแบบนี้:

| | ขั้น 4 เป็นเจ้าของ | ขั้น 5 เป็นเจ้าของ |
|---|---|---|
| ข้อความ | พิมพ์ว่าอะไร · ฟอนต์ · สี · อยู่ตรงไหน | เคลื่อนไหวยังไง · มีกล่องพื้นหลังไหม |

ผูกกันด้วย `id` ของกล่องข้อความ ผลคือ `captions.json` ไม่เคยถูกขั้น 5 แตะ และ
`final-text.mp4` ยังสร้างได้เหมือนเดิมทุกประการตลอดไป

[fxtext.py:29](vcut_engine/fxtext.py#L29) ยืมตัวประกอบสตริงของขั้น 4 มาใช้ทั้งดุ้น
(`_clock` `_colour` `_esc` `_place` `_tags`) และเรียก `caption.cues()` ตัวเดิมแล้ว
*แปลงเวลา* เอา แทนที่จะเขียนตัวคำนวณชุดที่สอง:

> "ข้อความชิ้นไหนโผล่บ้าง" จึงไม่มีทางตอบไม่ตรงกันระหว่างสองขั้น เพราะมันมาจาก
> ฟังก์ชันเดียวกัน

**invariant ที่บังคับตัวเองไว้:** `fx.json` ว่าง → `final-fx.mp4` ต้องเหมือน
`final-text.mp4` ทุกไบต์ของภาพและทุก sample ของเสียง [finish.py:114](vcut_engine/finish.py#L114)
จึงจงใจคงเส้น `-vf`/`-af` เดิมไว้เมื่อไม่มีภาพซ้อนและไม่มีเพลง แทนที่จะใช้
`filter_complex` ที่ให้ผลเท่ากัน — เพื่อให้ข้อความข้างบนเป็นสิ่งที่ *ตรวจได้ด้วยการ
เทียบไฟล์* ไม่ใช่สิ่งที่ต้องเชื่อ

## 5. ไปป์ไลน์เต็มและไฟล์ที่แต่ละขั้นเขียน

```
ฟุตเทจดิบ (โฟลเดอร์ .MOV)
   │
   ├─ scan ──────► manifest.json      ffprobe + motion + สว่าง + ดัง       [scan.py]
   ├─ thumbs ────► thumbs/*.jpg       ภาพตัวอย่าง + contact sheet 5×5      [thumbs.py]
   ├─ listen ────► transcript.json    ffmpeg→wav 16k → whisper.cpp        [listen.py]
   ├─ silence ───► silence.json       silencedetect หาช่วงเงียบ            [silence.py]
   ├─ ai ────────► ai.json            (ปิดได้) บท · คะแนน · ช่วงที่ควรเก็บ   [ai.py]
   │
   ├─ prepare ───► pool.json          ★ ดูทีละคลิป: แยกพูด/วิว ตัดช่วง      [prepare.py]
   ├─ compose ───► edl.json           ★ ดูทั้งกอง: หยิบชิ้นไหน เรียงยังไง   [compose.py]
   │
   ├─ render ────► segments/*.mp4     ตัด+แก้ทุกอย่างพาสเดียว (hash cache) [render.py]
   ├─ assemble ──► final.mp4          concat -c copy ไม่เข้ารหัสซ้ำ         [assemble.py]
   ├─ review ────► review.json        ให้ AI ดูผลแล้วเสนอแก้                [review.py]
   │
   ├─ caption ───► final-text.mp4     ★ ขั้น 4 · ซับ+ข้อความผ่านฟิลเตอร์ ass [caption.py]
   └─ fx ────────► final-fx.mp4       ★ ขั้น 5 · เอฟเฟกต์ทุกชั้นในพาสเดียว   [finish.py]
                                          └ fx.py · fxtext.py · overlay.py · music.py
```

**สามไฟล์ผลลัพธ์ ไม่ใช่ไฟล์เดียวที่ถูกเขียนทับสามรอบ** — `final.mp4` · `final-text.mp4` ·
`final-fx.mp4` อยู่ครบพร้อมกันเสมอ เปิดเทียบกันได้ทันทีว่าชั้นไหนทำให้อะไรเปลี่ยน
และขั้น 4/5 ไม่มีทางทำของขั้น 3 พัง เพราะมันอ่านอย่างเดียว

จุดที่ควรสังเกต:

**`prepare` กับ `compose` เป็นคนละงาน** — [decide.py:3](vcut_engine/decide.py#L3) อธิบายว่า
เดิมรวมกันแล้วผ่าออกเพราะ:

```
prepare  ดูทีละคลิป — ตัดช่วงไหน ใช้ได้ไหม      → pool.json
compose  ดูทั้งกอง — หยิบชิ้นไหนมาเรียงยังไง     → edl.json
```

พอมีไฟล์คั่นกลาง ขั้น "รวม" ถึงจะมีคลังให้เลือกจริง ๆ และเห็นได้ว่าชิ้นไหนอยู่ในคลัง
แต่ไม่ได้ถูกใช้ ส่วน `decide` เหลือหน้าที่เดียวคือเรียกสองตัวนี้ต่อกัน ให้คำสั่งเดิมยังใช้ได้

**compose มี 2 แกนที่แยกจากกัน** ([compose.py:1](vcut_engine/compose.py#L1)):

| `[compose] mode` — *เอาชิ้นไหน* | `[order] mode` — *เรียงยังไง* |
|---|---|
| `all` ทุกชิ้นในคลัง | `stage1` ลำดับที่คนลากจัดไว้ |
| `pattern` สลับตามรูปแบบ พูด→วิว→วิว | `pick` ตามที่วิธีเลือกจัดมา |
| `budget` กำหนดเวลารวมแต่ละแบบ | `date` วันที่ถ่ายจริง |
| `numbers` เลขคลิปที่ระบุ | `number` เลขบนชื่อไฟล์ |
| `timerange` ช่วงเวลาที่ถ่าย | `duration` ความยาวชิ้น |
| `manual` เลือกเองทีละชิ้น | `manual` ลำดับที่ลากไว้รอบก่อน |
| `ai` ให้ AI เลือกจากความหมาย | |

ใช้ข้ามกันได้ทุกคู่ — 7 × 6 แบบ

**การให้คะแนนช็อตพูด** [compose.py:51](vcut_engine/compose.py#L51) เป็น heuristic ล้วน:

```python
uniq = len(set(words))
fit = min(1.0, dur / 8.0) if dur < 8 else max(0.35, 8.0 / dur)
return round(uniq * (uniq / len(words)) * fit, 3)
```

**ความหลากหลายของคำ × ความเหมาะของความยาว** — ช็อตที่วนคำเดิม ("นายนายนาย")
ได้คะแนนต่ำ ไม่ได้ "เข้าใจ" อะไร ส่วนที่เข้าใจเนื้อหาจริงถูกโยนให้ AI ทำแทน

## 6. สิ่งที่เอนจินจงใจไม่ทำ

| ไม่มี | ผลคือ | ถ้าจะเติมต้องใช้ |
|---|---|---|
| scene detection | ไม่รู้ว่ากล้องตัดฉากตรงไหนในคลิปเดียว | PySceneDetect / `ffmpeg select='gt(scene,0.4)'` |
| face / object detection | ไม่รู้ว่าใครอยู่ในเฟรม จัดองค์ประกอบไม่ได้ | OpenCV / YOLO |
| speaker diarization | แยกไม่ได้ว่าใครพูด | pyannote |
| source separation | แยกเสียงคนออกจากเสียงรอบข้างไม่ได้ | demucs / spleeter |
| beat detection | ตัดตามจังหวะเพลงไม่ได้ | librosa |
| LUT / .cube | โทนสีมีแค่ 5 ชุดสำเร็จที่ประกอบจาก `colorbalance`+`eq` | `lut3d` filter |
| ทรานซิชัน | ต่อชิ้นแบบ cut ชนอย่างเดียว ไม่มีจาง/ปัด | `xfade` (เฟส D — ยังไม่ทำ) |

ทุกข้อในตารางนี้แลกมาด้วยสิ่งเดียวกัน: **ไม่ต้องลง dependency** และ **ผลลัพธ์
reproduce ได้ 100%** ซึ่งเป็นสองอย่างที่เอนจินนี้ให้ค่าสูงสุด

`ffmpeg select='gt(scene,...)'` เป็นตัวเดียวที่เติมได้โดยไม่ผิดหลักการ — น่าจะเป็น
ทางขยายที่ถูกที่สุดถ้าจะทำต่อ

### สองข้อที่เคยอยู่ในตารางนี้ แล้วหายไปแล้ว

**subtitle burn-in** กับ **color grading** เคยอยู่ในรายการ "จงใจไม่ทำ" ข้างบน
ตอนนี้ทำได้แล้วทั้งคู่ **โดยไม่ต้องลง dependency สักตัว** เพราะเครื่องมือที่ต้องใช้
อยู่ใน ffmpeg มาตั้งนานแล้ว:

```
ขั้น 4   ass filter (libass + harfbuzz)   →  ซับไทยจัดสระ/วรรณยุกต์ถูก
ขั้น 5   colorbalance · eq · hue          →  โทนสี 5 ชุด (warm/cool/punch/flat/bw)
        setpts + atempo                   →  สโลว์โม/เร่ง โดยเสียงไม่เปลี่ยนระดับ
        scale + crop                      →  ซูมเข้าโดยกรอบภาพไม่เปลี่ยน
        \p1 drawing ของ libass            →  ลูกศร/แถบ/จุด เป็นเวกเตอร์
        overlay + sidechaincompress       →  ภาพซ้อน + เพลงที่หลบเสียงพูดเอง
```

เส้นแบ่งที่แท้จริงจึงไม่ใช่ "ทำได้/ทำไม่ได้" แต่คือ **"ffmpeg ทำได้อยู่แล้วไหม"** —
สิ่งที่ยังเหลืออยู่ในตารางข้างบนคือสิ่งที่ต้องพึ่งโมเดล machine learning จริง ๆ
เท่านั้น (จำหน้า · แยกเสียง · หาจังหวะเพลง) ไม่ใช่สิ่งที่แค่ยังไม่ได้เขียน

## 7. ถ้าจะสร้างเอนจินแบบนี้เอง

สรุปเป็นสูตร:

1. **หาเครื่องมือที่ทำงานหนักได้อยู่แล้ว** — ffmpeg ทำได้เกือบทุกอย่างที่ video library
   ทำได้ และเร็วกว่า อย่าเขียน pixel loop ใน Python

2. **หาวิธี "วัด" แทนที่จะ "เข้าใจ"** — ไม่ต้องรู้ว่าในภาพมีอะไร แค่รู้ว่ามันสั่นไหม
   สว่างไหม ดังไหม มีคนพูดไหม ก็ตัดสินใจได้เกือบทั้งหมดแล้ว

3. **ให้ทุกขั้นเขียน JSON ที่คนอ่านออก** — debug ง่าย แก้มือได้ ทำ UI ทับได้
   และเป็นจุดที่คนเข้ามาแทรกการตัดสินใจได้ทุกเมื่อ

4. **cache ด้วย hash ของ "สิ่งที่มีผลต่อผลลัพธ์" เท่านั้น** — คิดให้ดีว่าอะไร*ไม่*ควร
   อยู่ใน hash ซึ่งสำคัญเท่ากับสิ่งที่ควรอยู่

5. **แยกการตัดสินใจออกจากการลงมือ** — เปลี่ยนใจแล้วต้องไม่ต้องทำงานหนักใหม่

6. **ให้ AI เขียนได้แค่ไฟล์ความเห็น** — แล้วให้กฎที่เขียนตายตัวเป็นคนตัดสินใจว่าจะ
   เชื่อแค่ไหน ระบบจะยัง deterministic และปิด AI ทิ้งเมื่อไรก็ได้

7. **ไม่ทิ้งข้อมูลที่คัดออก** — เก็บพร้อมเหตุผล ให้คนดึงกลับได้ ตัวกรองไม่ได้ถูกเสมอไป

8. **ตรวจงานตัวเองตอนจบ** — probe ไฟล์ผลลัพธ์กลับมาเทียบกับสิ่งที่ตั้งใจ แล้วรายงาน
   ความต่างออกมาให้เห็น
