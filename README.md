# vcut

ตัดต่อวิดีโออัตโนมัติจากฟุตเทจดิบทั้งโฟลเดอร์ ควบคุมทุกอย่างด้วยไฟล์ config

ออกแบบมาให้ **ไม่มี AI อยู่ในเอนจิน** — ทุกขั้นเป็น ffmpeg/whisper ล้วน คาดเดาได้
และให้ผลเดิมทุกครั้ง ส่วน AI เป็นชั้นบนที่เรียกเครื่องมือนี้อีกที (Phase 4)

```
ต้องมี:  ffmpeg + ffprobe  ·  Python 3.11+  ·  whisper.cpp (เฉพาะขั้นถอดเสียง)
ไม่ต้องลง dependency ใด ๆ — ใช้ stdlib ล้วน
```

---

## เริ่มใช้

```bash
./vcut run -c projects/phu-soi-dao.toml     # ทำครบตั้งแต่อ่านคลิปถึง final.mp4
./vcut info -c projects/phu-soi-dao.toml    # ดูสถานะโปรเจกต์
./vcut presets                              # ดูสูตรที่มี
```

## ขั้นตอน

แต่ละขั้นอ่านไฟล์ที่ขั้นก่อนหน้าเขียนไว้ ไม่มีสถานะซ่อนอยู่ที่ไหน
รันขั้นไหนซ้ำก็ได้ ขั้นที่ทำไปแล้วจะข้ามจาก cache

| คำสั่ง | อ่าน | เขียน | ทำอะไร |
|---|---|---|---|
| `vcut scan` | ฟุตเทจ | `.vcut/manifest.json` | ffprobe + motion + ความสว่าง + ความดัง ทุกคลิป |
| `vcut listen` | manifest | `.vcut/transcript.json` | แยกเสียง 16k → whisper.cpp → คำพูดพร้อมเวลา |
| `vcut thumbs` | manifest | `.vcut/thumbs/` | ภาพตัวอย่าง + contact sheet 5×5 |
| `vcut ai` | manifest + transcript + sheets | `.vcut/ai.json` | ถาม AI: แบ่งบท · ให้คะแนนช็อต · ช่วงที่ควรเก็บ |
| `vcut decide` | manifest + transcript (+ ai.json) | `.vcut/edl.json` | **★ ตัดสินใจว่าเอาช็อตไหน ยาวเท่าไร เรียงยังไง** |
| `vcut render` | edl | `.vcut/segments/` | ตัด + แก้ภาพ/เสียงในพาสเดียว (cache ด้วย content hash) |
| `vcut assemble` | segments | `final.mp4` | ต่อเป็นไฟล์เดียว ไม่เข้ารหัสซ้ำ |
| `vcut view` | ทุกอย่างข้างบน | `edl.json` | เปิดหน้าเว็บในเครื่อง ดู/แก้ EDL ด้วยตา |
| `vcut gc` | — | — | ลบ segment ที่ EDL ปัจจุบันไม่ได้ใช้ |

### `edl.json` คือสัญญากลาง

ไฟล์นี้คือหัวใจของทั้งระบบ — เป็น JSON ธรรมดาที่บอกว่าจะเอาช็อตไหน
ช่วงวินาทีไหน เรียงลำดับใด แก้ด้วยมือได้ แล้ว `render` / `assemble` ทำตามทันที

```
เปลี่ยนลำดับ / ลบช็อตออก   →  render ไม่ทำงานเลย (วัดจริง 0.1 วินาที)
เปลี่ยนความยาว B-roll      →  render ใหม่เฉพาะชิ้นวิว
เปลี่ยน preset ทั้งชุด      →  render ใหม่เฉพาะชิ้นที่พารามิเตอร์เปลี่ยนจริง
```

วัดจริงกับฟุตเทจชุดนี้ (220 ชิ้น · 22.9 นาที · 3.1 GB):

| งาน | เวลา |
|---|---|
| `render` ครั้งแรก | ~40 นาที |
| `render` หลังแก้ EDL (ไม่แตะพารามิเตอร์ภาพ/เสียง) | **0.1 วินาที** |
| `assemble` ต่อไฟล์ใหม่ทั้งเรื่อง | ~56 วินาที (คอขวดที่การเขียนดิสก์ 3.1 GB) |

commit `edl.json` เข้า git ได้ → ผลลัพธ์ reproduce ได้ 100%

## ปรับค่า

ทับค่าได้ 3 ทาง เรียงจากอ่อนไปแข็ง:

```bash
# 1) preset
./vcut decide -c hiking-vlog

# 2) ไฟล์โปรเจกต์ที่ extends preset
./vcut decide -c projects/phu-soi-dao.toml

# 3) ทับทีละค่าตอนสั่ง
./vcut decide -c projects/phu-soi-dao.toml --set broll.run_max=4 --set talk.min_shot=6
```

`./vcut config -c <ไฟล์>` แสดงค่าที่ merge เสร็จแล้วทั้งหมด

### ค่าที่ปรับบ่อย

| กลุ่ม | คีย์ | ความหมาย |
|---|---|---|
| `[talk]` | `gap_merge` | ช่องเงียบสั้นกว่านี้ไม่ตัด — สูงขึ้น = ตัดถี่น้อยลง |
| | `min_shot` | ช็อตพูดสั้นสุด กันตัดจนฟังไม่รู้เรื่อง |

| | `run_max` | วิวติดกันได้ไม่เกินกี่ชิ้น |
| | `drop_above_motion` | ทิ้งคลิปที่สั่นเกินค่านี้ (0 = เก็บหมด) |

## เรื่องที่เอนจินจัดการให้อัตโนมัติ

ทั้งหมดนี้แก้ในพาสเดียวตอน render — ไม่มีขั้น normalize แยก จึงเข้ารหัสรอบเดียว
ภาพคมกว่าและประหยัดดิสก์

| ปัญหา | วิธีแก้ |
|---|---|
| metadata rotation โกหก (คนนอนขวางจอ) | `[scan.rotation_overrides]` บังคับ transpose รายคลิป |
| คลิปกลับหัว 180° | ffmpeg autorotate |
| คลิปแนวตั้งในจอ 16:9 | เต็มความสูง + พื้นหลังเบลอ (ย่อ 480×270 ก่อนเบลอ เร็วกว่าหลายเท่า) |
| HEVC full range สีจัดกว่าคลิปอื่น | `[scan.color] full_range_clips` → แปลงเป็น tv range |
| fps ผสมหลายแบบ / VFR | บังคับ CFR 59.94 — ถ้าข้ามขั้นนี้เสียงจะเลื่อนสะสมจนปากไม่ตรง |
| เสียง mono ปนอยู่คลิปเดียว | อัปเป็น stereo ให้เท่ากันหมด |
| คลิปไม่มีเสียงเลย | ใส่ track เงียบให้ ไม่งั้น concat พัง |
| เสียงต้นฉบับเบามาก (−50 LUFS) | คำนวณ gain แบบรู้พีค แล้วให้ limiter แตะเท่าที่จำเป็น |

### ⚠️ บั๊ก `alimiter` ที่ต้องระวัง

`alimiter` ของ ffmpeg เปิดออปชัน `level` ไว้โดยดีฟอลต์ ซึ่ง **auto-normalize
สัญญาณขึ้นชนเพดานเสมอ ทับค่า gain ที่คำนวณมาทั้งหมด** ทำให้ true peak ทะลุ 0 dBFS
แม้ตั้ง limiter ไว้ต่ำแล้ว

vcut ตั้ง `level=disabled` ให้อัตโนมัติ (`[audio] limiter_level_disabled = true`)
อย่าปิดค่านี้ถ้าไม่รู้ว่ากำลังทำอะไร

### การคำนวณ gain

```
gain = min( เป้าความดัง − ความดังจริง ,  (เพดานพีค + allow_limit) − พีคจริง )
```

ถ้าดูความดังอย่างเดียว คลิปที่เบามากจะถูกเร่งจนพีคทะลุ แล้วโยนภาระให้ limiter
บีบจนเสียงแบน สูตรนี้กันไม่ให้ไปถึงจุดนั้นตั้งแต่แรก — `allow_limit` คือปุ่ม
แลกระหว่าง "เสียงสม่ำเสมอ" กับ "ไดนามิกเดิม"

| `allow_limit` | ช่วงกว้างของเสียงพูด | ชิ้นที่ limiter แตะ |
|---|---|---|
| 0 | 18.7 dB (ดัง-เบาสวิงมาก) | 0 |
| 4 | 14.7 dB | 73 |
| 8 | 10.7 dB | 30 |
| **12** (ดีฟอลต์) | **6.7 dB** | **11** |

## AI — ชั้นที่ปรึกษา ไม่ใช่ชั้นที่ลงมือ

กฎในเอนจินคัดช็อตได้ แต่ไม่รู้ว่าเรื่องเล่าถึงไหน — งานแบบ "เล่าตามลำดับการเดินทาง"
หรือ "เอาช่วงที่พูดวนซ้ำออก" ต้องมีคนอ่านเนื้อหาจริง

```bash
./vcut thumbs -c story-ai                 # AI ต้องมีภาพดูก่อน
./vcut ai -c story-ai --goal "ตัดเหลือ 10 นาที เล่าตามลำดับการเดินทาง"
./vcut decide -c story-ai                 # อ่าน ai.json — ไม่เรียก AI ซ้ำ
```

**AI เขียนได้ไฟล์เดียวคือ `.vcut/ai.json`** ซึ่งเป็นความเห็นล้วน ๆ:

```
chapters[]        แบ่งบท + ลำดับคลิปในบท
clips[].score     คะแนนความน่าเก็บ 0–1
clips[].keep      ช่วงวินาทีที่ควรเก็บ
clips[].drop      ควรทิ้งทั้งคลิป
```

`decide.py` เอาไปใช้ด้วยกฎที่เขียนตายตัวใน `[ai.apply]` ตัว AI ไม่เคยแตะ `edl.json` เอง

| คีย์ | ทำอะไร |
|---|---|
| `order` | เรียงคลิปตามบทที่ AI แบ่ง (`false` = เรียงตาม `[order]` เหมือนเดิม) |
| `drop` | ทิ้งคลิปที่ AI บอกว่าใช้ไม่ได้ |
| `trim` | ช่วงพูด: ตัดร่วมกับ VAD · ช่วงวิว: AI เลือกตำแหน่ง **แต่กฎยังคุมความยาว** |
| `score_weight` | น้ำหนักคะแนน AI ตอน `[select]` คัดช็อต (0 = กฎล้วน · 1 = AI ล้วน) |

ผลที่ได้จึงยังคาดเดาได้:

```
รัน decide ซ้ำกี่ครั้งก็ไม่เสียเงินเรียก AI ใหม่   →  ปรับสูตรได้ฟรีไม่จำกัด
commit ai.json เข้า git                        →  คนอื่นได้ผลเดียวกัน ไม่ต้องมี API key
--set ai.enabled=false                         →  กลับไปเป็นผลของ Phase 3 เป๊ะ ๆ
```

AI เห็นแค่ **ข้อความ + contact sheet 11 ภาพ** — ไม่มีการส่งไฟล์วิดีโอออกไปไหน
ทุกอย่างที่ส่งไปเก็บไว้อ่านย้อนหลังได้ที่ `.vcut/ai/<task>.prompt.md`

### พิมพ์ในแชท Claude Code ก็ได้

`.claude/skills/video-edit/SKILL.md` สอน Claude Code ให้แปลคำสั่งภาษาไทยเป็น
คำสั่ง `vcut` ให้เอง — พิมพ์ว่า *"ตัดเหลือ 10 นาที เล่าตามลำดับการเดินทาง"*
หรือ *"วิวติดกันเยอะไป"* แล้วมันจะเลือกคีย์ config ที่ถูกให้

## หน้าเว็บ — `vcut view`

```bash
./vcut view -c projects/phu-soi-dao.toml            # /       ดูและแก้ EDL
./vcut view -c projects/phu-soi-dao.toml --setup    # /setup  ตั้งค่าและสั่งรันทีละขั้น
```

สองหน้า เสิร์ฟจากเซิร์ฟเวอร์เดียว ด้วย stdlib ล้วน — ไม่มี npm ไม่มี build step
ไม่มี DB ไม่มี login ผูกกับ `127.0.0.1` เท่านั้นและตรวจ `Host` ทุก request
เครื่องอื่นในวงแลนต่อไม่ได้

### `/setup` — ตั้งค่าและเลือกว่าจะรัน Phase ไหน

แบ่งเป็น 4 การ์ด เปิด/ปิดได้ทีละ Phase

```
Phase 1  เตรียมวัตถุดิบ    scan → thumbs → listen
   ↓
Phase 2  ความเห็น AI       ai
   ↓
Phase 3  ตัดสินใจ          decide
   ↓
Phase 4  ผลิตไฟล์          render → assemble
```

⚠️ **เลขในหน้านี้ไม่ตรงกับเอกสารแผนที่ตั้งไว้ตอนแรก และตั้งใจให้ไม่ตรง** — เลขในแผน
คือลำดับที่*สร้าง*ระบบขึ้นมา ส่วนเลขในหน้านี้คือลำดับที่มัน*ทำงาน* ถ้ารันเรียง 1→2→3→4
ตามแผนเดิมจะกด render (Phase 2 เดิม) ก่อน decide (Phase 3 เดิม) แล้วพังทันที

| หน้านี้ | เอกสารแผนเดิม |
|---|---|
| Phase 1 · เตรียมวัตถุดิบ | Phase 1 · SCAN + LISTEN |
| Phase 2 · ความเห็น AI | Phase **4** · AI + SKILL |
| Phase 3 · ตัดสินใจ | Phase **3** · DECIDE + PRESET |
| Phase 4 · ผลิตไฟล์ | Phase **2** · RENDER + ASSEMBLE |

การ์ดทุกใบกำกับชื่อจากแผนเดิมไว้ให้เทียบกันได้

**สวิตช์ "รัน" กับสวิตช์ "ใช้ AI" คนละเรื่องกัน** — จุดนี้ผิดกันบ่อย:

```
ปิด "รัน" ของ Phase 2   →  ไม่ถาม AI ใหม่ แต่ยังใช้ ai.json เดิมอยู่  (ประหยัดเงิน ผลเท่าเดิม)
ปิด [ai] enabled        →  ไม่เอาความเห็น AI ไปใช้เลย               (ผลกลับเป็นกฎล้วน)
```

ตัวเลือกเก็บที่ `[run]` ในไฟล์โปรเจกต์ — `./vcut run` อ่านจากที่เดียวกัน หน้าเว็บกับ
เทอร์มินัลจึงทำเหมือนกันเสมอ:

```toml
[run]
prepare = true    # Phase 1
advise  = true    # Phase 2
decide  = true    # Phase 3
produce = true    # Phase 4
```

```
$ ./vcut run -c projects/phu-soi-dao.toml
แผนการรัน  ตัดสินใจ → ตัดเป็นชิ้น → ต่อเป็นไฟล์
  ข้าม อ่านคลิป — ปิด Phase 1 ไว้
  ข้าม ถาม AI — ปิด Phase 2 ไว้
```

ปุ่ม **สร้างไฟล์** ในหน้าหลักทำตามแผนนี้ และขึ้นกล่องยืนยันบอกก่อนเสมอว่าจะรันอะไรบ้าง
ข้ามอะไรเพราะอะไร และใช้เวลาประมาณเท่าไร

### ราคาของการแก้ค่า

ทุกช่องติดป้ายราคาไว้ และแผงขวาคำนวณให้สด ๆ ทุกครั้งที่ขยับ:

```
เลื่อน talk.min_shot 3 → 6      →  render ใหม่ 37 ชิ้น · ประมาณ 8 นาที · ได้ 24:04
เลื่อน audio.allow_limit 12 → 4  →  render ใหม่ 75 ชิ้น · ประมาณ 14 นาที
เลื่อน broll.run_max 3 → 2       →  ไม่ต้อง render ใหม่ · ได้ 22:03
```

ตัวเลขนี้**แม่นจริง ไม่ใช่การเดา** และคำนวณเสร็จใน 0.02 วินาทีโดยไม่เรียก ffmpeg
เลยสักครั้ง — ทำได้เพราะชื่อไฟล์ segment คือ sha1 ของทุกพารามิเตอร์ที่มีผลต่อชิ้น
นั้น คำนวณ hash แล้วดูว่ามีไฟล์อยู่หรือยัง ก็รู้คำตอบทันที ส่วนอัตราวินาที/ชิ้น
มาจากที่ `render` วัดไว้จริงในรอบก่อน

| ระดับราคา | คีย์ | ผลของการแก้ |
|---|---|---|
| ไม่ต้องทำอะไรใหม่ | `render.workers` `project.out` | 0 |
| decide + ต่อไฟล์ใหม่ | `talk` `broll` `order` `select` `ai.apply` | ~35 วิ |
| ทำภาพตัวอย่างใหม่ | `thumbs` | ~2 นาที |
| ถาม AI ใหม่ | `ai.model` `ai.goal` `ai.tasks` | 5–20 นาที · เสียเงิน |
| ถอดเสียง/อ่านคลิปใหม่ | `listen` `scan` | 12–40 นาที |
| render ใหม่ทุกชิ้น | `video` `encode` `audio` | ~40 นาที |

แท็บ **TOML ดิบ** แก้ได้ครบทั้ง 99 คีย์ ไม่จำกัดแค่ที่ฟอร์มมีให้ กดบันทึกแล้ว
ระบบลองโหลดดูก่อน ถ้า config ใช้ไม่ได้จะไม่เขียนทับไฟล์เดิม

การบันทึกจากฟอร์ม**แก้ทีละบรรทัดในไฟล์เดิม** ไม่ได้เขียนทับทั้งไฟล์ — คอมเมนต์
ที่อธิบายเหตุผลไว้และคีย์ที่ฟอร์มไม่รู้จักจึงอยู่ครบทุกตัว

### `/` — ดูและแก้ EDL

| ทำได้ | ทำไม่ได้ (ตั้งใจ) |
|---|---|
| ดูช็อตทั้งหมดพร้อมภาพ คำพูด คะแนน AI | ตัดต่อในเบราว์เซอร์ |
| กดฟัง/ดูชิ้นที่ render แล้วจริง ๆ | ยืด-หด ความยาวช็อต |
| เอาช็อตออก · เอากลับ · เอาออกทั้งบท | เปลี่ยนค่า config |
| ลากสลับลำดับ · ปุ่ม ↑↓ · คีย์ `j k x J K` | อัปโหลดฟุตเทจ |
| กด **สร้างไฟล์** แล้วดู log ไหลสด ๆ | |
| **ย้อนกลับ** ไปฉบับก่อนบันทึกล่าสุด | |

เบราว์เซอร์ทำได้แค่ *เอาออก* กับ *สลับลำดับ* — ซึ่งเป็นสองอย่างที่ **ไม่ต้อง render ใหม่**
ทุกอย่างที่เหลือยังเป็นงานของ config เหมือนเดิม วัดจริงกับฟุตเทจชุดนี้:

```
เอาช็อตออก 3 ชิ้น + สลับลำดับ → กดสร้างไฟล์ → final.mp4 ใหม่ใน 31 วินาที
(render 217 ชิ้น: cache ทั้งหมด · ใหม่ 0)
```

ทุกครั้งที่บันทึก ฉบับก่อนหน้าถูกสำรองไว้ที่ `.vcut/edl.prev.json` เสมอ

## cache

```
.vcut/
├─ manifest.json      คุณสมบัติคลิป — cache ด้วย (ขนาด + mtime)
├─ transcript.json    คำพูด — cache รายคลิป
├─ loudness.json      ผลวัดเสียงรายช่วง
├─ ai.json            ★ ความเห็น AI (commit ได้)
├─ ai/                prompt ที่ส่งไป + คำตอบดิบ
├─ edl.json           ★ สัญญากลาง
├─ edl.prev.json      ฉบับก่อนหน้าที่ viewer สำรองไว้ให้
├─ render.json        map ชิ้น → ไฟล์ segment
├─ whisper/           ผลดิบจาก whisper.cpp
├─ thumbs/            ภาพตัวอย่าง + sheets/
└─ segments/          <content-hash>.mp4
```

ลบ `.vcut/` ทั้งโฟลเดอร์ได้เสมอ — สร้างใหม่ได้จากฟุตเทจ + config
`vcut gc` ลบเฉพาะ segment ที่ EDL ปัจจุบันไม่ได้ใช้ · `vcut gc --all` ลบทั้งหมด

**ถ้ามี transcript จากงานรอบก่อนอยู่แล้ว** ชี้ `[listen] import_dir` ไปที่โฟลเดอร์นั้น
จะข้ามขั้นถอดเสียงทั้งหมด (ประหยัดสิบกว่านาทีต่อชั่วโมงฟุตเทจ)

## ข้อจำกัดที่ควรรู้

- `[render] workers` ตั้งไว้ 2 เพราะ videotoolbox บน M3 เป็นคอขวดอยู่แล้ว เพิ่มแล้วไม่เร็วขึ้น
- `[listen] workers` ต้องเป็น 1 บนเครื่อง RAM 8 GB — whisper large กิน RAM หนัก
- `assemble` แบบ stream copy ต้องการให้ทุก segment เข้ารหัสด้วยพารามิเตอร์เดียวกัน
  เปลี่ยน `[encode]` แล้วต้อง render ใหม่ทั้งหมด
- ความยาวไฟล์ผลลัพธ์อาจต่างจาก EDL ระดับเสี้ยววินาที จาก keyframe ที่ไม่ตรงพอดี
- `select` ตัดด้วยกฎ (ความหลากหลายของคำ + ความนิ่งของภาพ) **ไม่ใช่ความเข้าใจเนื้อเรื่อง**
  การแบ่งบทตามการเดินทางต้องรอ Phase 4
